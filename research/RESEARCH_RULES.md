# Stable research rules

This condensed guide supplements, and does not replace, [AGENTS.md](../AGENTS.md) and the authoritative [canonical context](ROSA_RESEARCH_CONTEXT.md), particularly §§0–4, 12 and 14 and applicable later updates. Load the named sections for the mandatory research preflight; retrieve other sections when relevant. Resolve conflicts by inspecting dated original evidence and current user instructions; do not silently drop an existing gate.

- Objective: reduce unnecessary model decisions, native work, tokens, latency or total cost while preserving supported, complete, safe answers and user-requested order. Keep semantic interpretation with the model when judgment is needed; a descriptive infrastructure change is not automatically a research contribution.
- Before a research proposal, substantial research decision, implementation or experiment apply all five questions in context §12.2 and make the decision record in §14.2. Identify the observed opportunity, candidate/control action difference, closest prior mechanisms, fair evaluation/costs, and smallest decision-changing action and stop rule. Mark a material unknown or contradiction **BLOCKED / NOT YET JUSTIFIED**. A narrowly scoped diagnostic needs its own frozen protocol, resource cap and authorization.
- Screen original prior art and the nearest negative study. A named mechanism, fewer calls, successful invocation or equal output does not establish novelty, authorization, semantic equivalence or useful savings. Review earlier AI work critically against sources and raw records.
- Freeze hypothesis, tasks, independent postconditions, controls, budgets, metrics and stopping criteria before evaluation. Use equally capable strong ordinary controls, including applicable batching, reuse, concurrency and already-paid information. Remove conflicting sequential-only prompt instructions when a batching-enabled control requires it and show actual adoption. Record all costs, errors, exclusions, denominators, seeds and protocol revisions.
- Keep held-out task-level material and candidate-specific held-out opportunity counts in custodian storage. Use development evidence for method decisions. Prepare any held-out design-rules note only after the method freeze is confirmed.
- Label simulation, fixtures, retrospective replay and live ROS/LLM work accurately; distinguish observations, historical reports, inference and unknowns. Preserve failures and null results. A trace or tool request alone is not proof of execution or complete answer support.
- Preserve source, protocols, raw evidence, provenance, hashes, prior revisions and teammate work. Existing historical folders and archived packets are evidence, not automatic instructions. Do not alter baseline, run physical/production systems, move historical experiments, rewrite Git history, push or merge without explicit authorization.
- Update [active state](ACTIVE_STATE.md) only after a material state change, replacing superseded summary text and linking dated immutable decisions and evidence. Update canonical context as its governance requires; explicitly synchronize external project sources when requested. Coordinate a single writer for shared notes; inspect Git status and diffs, including untracked files, before handoff.
