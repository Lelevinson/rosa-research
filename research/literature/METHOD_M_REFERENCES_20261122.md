## 1. Fixed short tool menu

**Local implementation and origin.** For the inspection workload, `DOMAIN_TOOLS` lists the 12 read/log tools. `Arm.base_menu()` adds `final_answer`. `ArmTracedModel._generate()` calls `Arm.visible_schemas()` before sending each model request, so the transmitted list contains 13 entries. `Arm.execute()` also rejects tools outside the offered menu and explicitly blocks the two write tools. C1 applies the same set across question requests. Its code does not rank schemas from the current question or observation. ROSA already supports tool registration and tool exclusion. C1 brings its own fixed inspection set to the model-facing binding and checks dispatch in the research harness. [Pilot menu](../studies/small_model_harness_20261115/harness.py#L39), [schema filtering](../studies/small_model_harness_20261115/harness.py#L268), [model binding](../studies/small_model_harness_20261115/run_pilot.py#L107), [dispatch](../studies/small_model_harness_20261115/harness.py#L328), [stock ROSA tool construction](../../src/rosa/rosa.py#L269), [stock package filtering](../../src/rosa/tools/__init__.py#L91)

## 2. Structured finish tool

**Local implementation and origin.** The pilot design already specified `final_answer(answer: object)`. A valid, nonempty answer object sets the executor's finish flag and supplies the returned payload without another model request. The handler also describes one corrective attempt for an invalid submission reaching it, with a fallback on the second such submission. Ordinary argument pre-check is a separate path. The scorer records how the episode ended and can also recover JSON from a plain-text ending. Acceptance of an object by the executor checks its shape. Independent scoring checks requested fields, values and evidence. [Schema](../studies/small_model_harness_20261115/harness.py#L116), [termination hook](../studies/small_model_harness_20261115/harness.py#L157), [finish handler](../studies/small_model_harness_20261115/harness.py#L462), [scorer decision](../decisions/2026-11-15-scorer-v2.md)

## 3. Errors as text and strict argument pre-check

**Local implementation and origin.** C1 wraps ROSA tools with LangChain `StructuredTool`. For dict input, `PilotTool._parse_input()` checks the converted schema before Pydantic parsing can coerce it. The local pre-check covers represented JSON types, required fields, enums, and some nested structures and alternatives. The supported checks cover a subset of the JSON Schema specification. For example, a string supplied where an array is expected can produce a field-level diagnostic before calling the underlying tool. `Arm.call_inner()` converts ordinary exceptions into `ToolException`. With the configured LangChain handlers, these and argument validation failures become tool observations that the model can act on. Stock ROSA already enables handling for **agent output parsing errors**. E0/E1 separately add tool failure feedback to the stock executor through the existing LangChain callbacks. [C1 schema check](../studies/small_model_harness_20261115/harness.py#L63), [pre-check](../studies/small_model_harness_20261115/harness.py#L142), [wrapper configuration](../studies/small_model_harness_20261115/harness.py#L298), [exceptions](../studies/small_model_harness_20261115/harness.py#L359), [stock executor](../../src/rosa/rosa.py#L256), [E0/E1 code](../studies/fairness_errors_as_text_20261117/fair_arms.py#L28)

## 4. Final-answer ROS name normalization

**Local origin.** Round 1's answer checker already collected fully qualified names and found suffix matches. Round 2 reused this to develop a shadow-only final-answer rewrite, which scored possible changes without submitting them. The applied-test preflight found silent value loss in the old collision cases, so the owner approved a separate v2 rule for nested-object and list collisions. The experiment applied v2 at submission and retained the raw answer. The final `ExamArm.final_answer_tool()` reuses it, logs the changes, and passes the resulting answer to the existing finish handler. [Round 1 ledger and matcher](../studies/build_round1_20261115/answer_gate.py#L38), [Round 2 shadow path](../studies/build_round2_20261116/round2_harness.py#L133), [collision preflight](../studies/name_fix_applied_20261117/PREFLIGHT_COLLISION.md), [applied rule note](../studies/name_fix_applied_20261117/PROTOCOL_NOTE.md), [exam hook](../studies/exam_arms_20261121/exam_arms.py#L59)

**Exact behavior.** If the observed-name set contains only `/lab/camera` ending in the path segment `camera`, the eligible answer value `"camera"` can become `"/lab/camera"`. If both `/lab/camera` and `/test/camera` are in that set, it is left as written. The candidate set comes from absolute names found in task text and successful output portions. It is an episode-local set, and a name parsed from task text can refer to an entity that is absent. The code matches name-like string values and nested keys, preserving top-level answer keys. It keeps exact names and suppresses colliding renames. The code checks unique suffixes **before** logging `reject_never_seen`, so even an unmatched absolute-looking input can be expanded if a unique longer suffix match exists. This is important when describing the rule. A suffix unique in the observed set can still be ambiguous in the underlying graph. The rewrite submits the modified answer with no additional inference or native ROS action. ## Citation wording supported by the audit

The source trail supports describing the work as an **empirical ROSA systems study** of a fixed inspection interface, structured submission, tool-failure feedback, and evidence-limited ROS name normalization for local models. Cite Royce et al. and Yao et al. for the foundation, Zambelli for the nearest evaluated framework, *Less is More* and CMTF for tool-exposure policies, SCA for formal runtime feedback, and the ROS 2 design documents for the namespace semantics. Attribute the exact menu and rewrite to their local definition and tests. Describe MetaTool separately as the source for the experimental planning port. For results, cite the local development evaluation and retain its control and denominator qualifications. The audit provides no basis for a first-of-its-kind claim, an isolated causal gain for all four parts, or a held-out performance claim.
