# Offline sizing of four candidate mechanisms: frozen protocol

Dated 2026-11-20, Asia/Taipei. Source of the rules, measures and bars: `Claude outputs/2026-11-20_CC_OFFLINE_SIZING.md` (lead researcher, ROSA-Claude-Context mirror), which replaces PROMPT 3 of `2026-11-20_IDEA_SEARCH_PROMPTS.md`. Written and hashed (`FREEZE.json`) **before** `size_candidates.py` exists and before any candidate count exists. Offline, CPU only (`nice`), saved traces only: no model, no Ollama, no GPU, no ROS, no held-out or custodian file, no production-code change. **Label: sizing measurement on development tasks; no mechanism is built or tested; nothing here is a held-out or causal result.** Scorer v2.0 (`residual_failures_20261115/scorer_v2.py`) is used unchanged.

## 0. Preflight record (AGENTS.md; context Sections 12.2 and 14.2)
- **Observed opportunity and evidence:** loss map (`loss_map_20261120/REPORT.md`): 1,655 requests against a floor of 832; excess classes name guessing 147, recovery 71, batchable serial reads 248, repeats 157; 107 of 111 `param_list` calls followed by `param_get`; runaway episodes hold 23% of the excess. This study measures whether four candidate mechanisms could touch that opportunity safely.
- **Candidate vs control action difference:** C1 executes a not-found call on a unique ledger name instead of returning the error (the control retries alone); C2 answers a reverse relation in one call instead of a scan; C3 returns parameter values in the list result instead of a later `param_get`; C4 offers only `final_answer` after k requests with nothing new instead of continuing.
- **Closest prior mechanisms (read, not re-run):** name-fix v2 at the answer (`name_fix_applied_20261117`, applied; input side counted in `candidate_counts_20261118` (a) on three stage-3 tasks); list sweep (`decisions/2026-11-17-list-sweep-whole-cost.md`: whole-episode tokens -1.4%, native operations +7.8%, benefit not demonstrated); stall hint v2 (closed, failed its offline bar) and the parked stall breaker (NO-GO) for C4; finish-gate check and canonical rendering (class B) for answer-side formatting. Whether any candidate is the same mechanism as these is **not** claimed here.
- **Fair evaluation and cost:** sizing only. Costs are requests and estimated input tokens from saved traces; no control arm exists, so every "saved" number is an upper bound ("saved-max"), not a measured saving.
- **Smallest decision-changing next action and stop rule:** this offline count. A PASS only means "safe and large enough on saved traces"; building any arm needs its own frozen protocol and the owner's authorization. This study stops after `REPORT.md`.

## 1. Populations
- **P1** = the 288 loss-map episodes (seeds 5-8; 18 development tasks x 4 models; FULL arm), rows from `research/_artifacts/exam/lossmap/RESULTS_LOG_all.jsonl`, traces under `research/_artifacts/exam/lossmap/runs_all/`. Total requests 1,655.
- **P2** = the 1,832 saved episodes of `candidate_counts_20261118`, loaded with its `load_population()` and `parse_episode()` (same selection, same exclusions, no B0 exclusion). **Label: P2 is not independent of P1** (same task families, fixtures and models; different seeds and arms with different harness features, so mechanism firing rates in P2 describe those arms, not the FULL arm). P1 and P2 are always reported separately; P2 is never added to P1.
- Parsing: `offline_replay_20261116/episodes.py::parse` (requests, units, calls; list arguments expand to one call per entity). A call is `ok` when the parser says so; a **harness error** is a call the harness rejected (parser's `harness_error`). Models: lfm3:1.7b, qwen3.5:9b, gpt-oss:20b, bonsai-2:4b. Every measure is reported **per model and per task**.
- Bars are evaluated on P1 for size (S) bars and on **P1 and P2** for harm (H) bars, as in the source file for C1 H1; the same reading is applied to the other H bars and written next to each bar.

## 2. Classes
PASS = all bars of the candidate met. FAIL-HARM = any harm bar missed (the candidate stops; its size is still reported). FAIL-SIZE = harm bars met but a size bar missed. Harm is checked first. Bars are the numbers of the source file; no bar is changed.

## 3. Common definitions
- **Name ledger** (exact definition: `name_fix_applied_20261117/LEDGER_DEFINITION.md`; code `build_round1_20261115/answer_gate.py::allowed_names`). Two variants, fixed now:
  - **L-res (primary for C1; the source file says "names seen in earlier tool results")**: `allowed_names("", outputs of all calls of strictly earlier requests)`, i.e. names in successful results only, including the ledger's joined names (node name + namespace) and node-list entries. Task-text names are **not** in L-res.
  - **L-task (secondary, reported beside it)**: the name-fix ledger with the task text added (`allowed_names(task_text, ...)`), the one `candidate_counts_20261118` (a) used.
  - Calls in the same request do not see each other (conservative: with execution in the same request a later call could see an earlier call's result).
- **Needed-entity set N(task)** (fixture truth, used only to judge a binding after the fact): every absolute name that appears as a string, key or value, at any depth, in `task["answer"]`, plus every entity name in `task["support"]` (a `text` fact that is a name, the node of a `param` fact, the name of an `absent` fact).
- **Absent-entity tasks:** `template == "absent"` (`e1h_abs_1`, `e1h_abs_2`, `nf_absent`); the absent name A is the `absent` support fact.
- **Token estimate:** characters / 4 (an estimate, as in `candidate_counts_20261118`); never a tokenizer count. Input tokens of a request are the measured `usage.input_tokens` of its model call.
- **Saved-max** is always an upper bound under the most favourable reading below; a request is counted once per candidate. Support facts are judged with scorer v2.0 `support_missing(task, rows)`; "at request i" means rows of the events up to the end of request i's tool calls (events before the model_start of request i+1).

## 4. Candidate 1: ledger name resolution at input (+ existing output rewrite)
**Rule IN (as in the source file).** A *fire* is a call such that: (1) it is a menu tool call whose entity argument (the parser's entity arguments: node, topic, service, and the node of a parameter call; list arguments item by item) returned not-found (`ok` false, not a harness error, `NOT_FOUND` regex of `episodes.py` matches its text); (2) the typed string matches `RELATIVE_NAME` and has no leading "/" (absolute paths are never rebound); (3) the candidates are the L-res names whose trailing whole path segments equal the typed string exactly, case-sensitive (`answer_gate.trailing_matches`); (4) exactly one candidate R gives a fire with resolution R; 0 or 2+ candidates leave the error unchanged. A typed string that is itself a ledger name cannot occur (no leading slash). The L-task variant is computed the same way.
**Measures.**
1. Fires (P1, P2; per model, per task; L-res primary, L-task beside it); episodes with a fire; fires whose R appears **only as a joined name** (not contiguously in any successful result text) listed separately; fires where typed equals R without its leading slash ("slash-only").
2. **Truth of each binding** against N(task), in this order: *absent-made-present* if the task is an absent-entity task and typed is a trailing-segment suffix of A (the model asked about the absent entity in short form; binding replaces it by another real entity); else *needed* if R is in N; else *wrong* if some n in N ends with "/"+typed (the typed string abbreviated a needed entity and the binding chose another); else *not needed* (R is real but the task does not need it; harmless-looking but not a gain). Counts per class; every wrong and absent-made-present case is listed with its trace path. Also: fires inside absent-entity tasks (any), and fires where a later call of the model used a different entity for the typed string (`differ`, as in `candidate_counts_20261118`).
3. **Saved-max requests:** for a fire in request r, let k be the first later request that contains an `ok` call of the same tool on R (normalised with a leading slash). Saved-max = k - r (every request from r+1 to k could be skipped: recovery requests and the repeated call itself; an upper bound because those requests may also hold unrelated reads). No such k: 0 and the fire is listed `no_later_use`. Requests are counted once per episode as the union of the intervals (r, k]. Also the median and mean of k - r.
4. **Coverage (P1 only; labels from `loss_map_20261120/labelled_lossmap.jsonl`):** of the 147 `name_guess` and 71 `name_recovery` requests, how many are fire requests (guess) or lie in an interval (r, k] (recovery or other typed requests), and how many of the 218 are inside the saved-max set.
5. Fires inside the 45 unsupported P1 episodes (by failure type of the loss map).
6. **OUT replay (P1; P2 beside it):** apply `name_fix_applied_20261117/namefix_rule.py::rewrite_answer` unchanged (ledger = task text + all successful results of the episode, same call as `namefix_arm`) to the episode's final answer object, rescore with scorer v2.0, and report flips in both directions (supported to unsupported, unsupported to supported), the rewritten episodes, and which of the 26 `wrong_conclusion_facts_present` episodes of the loss map flip.
**Bars.** H1: 0 wrong bindings and 0 absent-made-present in P1 and in P2. S1: saved-max >= 3% of P1 requests (>= 50 of 1,655) OR >= 25% of the 218 guess+recovery requests (>= 55). S2: fires in >= 3 models and no task holds more than 60% of the fires (P1; fires with L-res). H2: OUT replay supported to unsupported = 0 (P1; P2 reported).
*Refinement recorded before counting:* the source rule says "names seen in earlier tool results", so the primary ledger excludes task-text names; `candidate_counts_20261118` used the task-text ledger, hence both are reported.

## 5. Candidate 2: reverse lookups in one call
**Step A (code check; reported first).** Read `src/rosa/tools/ros2.py` for the 12-tool menu (`read_log`, `ros2_doctor`, `ros2_node_info`, `ros2_node_list`, `ros2_param_get`, `ros2_param_list`, `ros2_service_info`, `ros2_service_list`, `ros2_topic_echo`, `ros2_topic_info`, `ros2_topic_list`, `roslog_list`; the `tools_offered` event of a trace) and, for each relation (service to providing node, topic to publisher and subscriber nodes, parameter name to nodes that have it), state whether the reverse direction is already one call; quote the code path and one saved result (path of the trace). No count is needed.
**Step B (traces).** Definitions fixed now:
- **Node-read call:** `ros2_node_info`, `ros2_param_list` or `ros2_param_get` with a node entity (any outcome).
- **Linked node name at request i:** a name that equals the task-text name, or occurs (as a name, including joined names) in a successful result of a strictly earlier request **other than** an enumeration (`ros2_node_list`, `ros2_param_list` without node). A **probe** is a node-read call on a node that is not linked at that request (the model reads it without a relation having pointed to it: it came from an enumeration or from a guess).
- **Probe request:** a non-final request whose calls are all node-read calls, at least one a probe, and no non-probe node-read call.
- **Scan:** a maximal run of >= 2 consecutive probe requests in which every request after the first reads at least one node not read earlier in the run. Scan length L = number of requests of the run; **saved-max of a scan = L - 1** (one reverse call replaces the run).
- **Gate (as written in the source file, "the needed entity is a service, topic or parameter the model already knows by name"):** the task text contains at least one absolute name or single-quoted token. This is satisfied by nearly every task, so the gate is nearly vacuous; scans are therefore reported by task together with the task's stage text so the reader can judge. Scans containing a `ros2_param_get` are reported apart (parameter-name lookups) from those with only `ros2_node_info`/`ros2_param_list`.
- **Derived-name guess:** a failed not-found call whose node entity N (not in the ledger L-task) has a last segment s such that, for some service or topic name S known before the call (names in successful `ros2_service_list` / `ros2_topic_list` results or entity arguments of successful `ros2_service_info` / `ros2_topic_info` calls), the last segment of S starts with s and what follows is empty or begins with "_" (example: node `/plant32/cedar` from service `/plant32/cedar_reset`). Counted per call, per episode, per task.
- **Aggregation size estimate (names only):** for each scan, the distinct nodes read in the scan whose successful result contains any task-text name or single-quoted task token; estimated tokens = total characters of those node names / 4. Reported with the measured input tokens of the scan's saved requests.
**Measures.** Scans; requests in scans; saved-max; derived-name guesses; unsupported episodes (P1: 45) containing a scan or a derived guess, by task; per model, per task; the size estimate. P2 reported beside P1.
**Bars.** S1: saved-max (scans only; derived guesses are reported, not added) >= 3% of P1 requests (>= 50). S2: scans in >= 2 models AND in >= 2 tasks (if all scans are in task `v2`, class FAIL-SIZE with the label "one task only"). H1: report only (no live harm can be measured offline).

## 6. Candidate 3: list results carry values
**Rule.** `ros2_param_list` returns `name: value` for each parameter when the whole result is <= 2,000 characters; above that it stays names only.
**Value text.** Inline text = the part of a saved `ros2_param_get` output after "value is: ", stripped (for example `Integer value is: 74\n` gives `74`). For a (node, parameter) read in the episode that value is used; for others the median length of inline values of the same parameter name over the population, else the median over all values of the population (an estimate, deterministic, computed by the script and printed).
**Measures (successful `ros2_param_list` calls; a call without node argument is one call over all returned nodes).**
1. Calls, calls followed later by a successful `ros2_param_get` on the same node (the loss map found 107 of 111), and for those whether the parameter name read was already known **before the list** (in the task text, or in an earlier successful result) so that the list was avoidable.
2. **Inline size:** result characters with values (JSON text of the list result with `name: value` entries) vs 2,000; share of calls above the cap (these stay unchanged and save nothing).
3. **Saved-max requests:** a request after an eligible (successful, under cap) list of node N in which **every** call is a successful `ros2_param_get` on (N, p) with p in that list and the **first** successful read of (N, p) in the episode (repeat reads are not answered by an earlier inline value). One count per request. Gets in `e1h_chg_*` tasks are counted but flagged (a value inline in an earlier list could be stale after the scripted change).
4. **Added tokens:** for each eligible list call, added characters = inline text length + 2 (": ") per parameter; added tokens = chars / 4; **carried cost** = added tokens x (number of later requests of the episode), because the values ride in every later request's context; per episode the sum over its eligible lists. **Saved tokens** = sum of measured `input_tokens` of the saved-max requests (generous to the candidate). Reported total, per model and number of episodes where added exceeds saved.
**Bars.** S1: saved-max >= 2% of P1 requests (>= 34). S2: saved requests in >= 2 models. H1: added input tokens over the episode (carried cost) < tokens of the saved requests (P1 total and per model reported; **the bar is applied to the P1 total and to the P2 total**).

## 7. Candidate 4: no-progress stop (runaway guard)
**Definitions.** The *strings* of a text are its tokens matched by `[^\s"'{}\[\],:;()=]+` (names and values; case-sensitive). The **seen set** before request i = strings of the task text and of all earlier results that were not rejected by the harness (successful or failed tool results; the model's own arguments are not included). A request is **novel** if any of its **successful** results (non-final calls with `ok` true, not harness errors) contains a string not in the seen set; a request with no successful result is non-novel. The first request of an episode is judged against the task-text strings only.
**Trigger at k** (k = 4, 5, 6): the first request i, not the last request of the episode, after which the last k requests are all non-novel; once per episode. On trigger the system would offer only `final_answer` on the next request; the forced answer would be request i+1.
**Measures per k (P1 and P2; per model, per task).** Episodes with a trigger; of those, ended supported, unsupported, capped (>= 40 requests and no accepted answer); **harm** = supported episodes at whose trigger `support_missing(task, rows up to request i)` is not empty; for unsupported episodes with a trigger, whether all support facts were present at the trigger (a forced answer could then be right; whether it would be right is not known offline). **Saved-max requests** = requests after the forced answer, i.e. n - (i+1), in episodes that ended unsupported or capped (the looser count n - i is also given); the same for the measured input tokens of those requests. How many of the 5 capped P1 episodes trigger and at which request. **Scripted-change tasks (`e1h_chg_*`) separately:** any trigger at which `support_missing` is not empty (the scripted change not yet observed) counts as harm there, whatever the episode ended as.
**Bars.** H1: harm = 0 at the chosen k in P1 and in P2, the chosen k being the smallest of 4, 5, 6 with 0 harm in both (report the smallest k with 0 harm in P1 and in P2 separately as well); if none, FAIL-HARM. S1: saved-max at the chosen k >= 3% of P1 requests (>= 50).

## 8. Report extras
- One table: candidate x (P1 saved-max requests, % of 1,655, models, tasks, harm count). For C4 the chosen k, or k = 6 if no k has 0 harm, is used and labelled.
- **Overlap (P1):** the sets of (episode, request) counted by each candidate (C1 interval requests; C2 scan requests after the first; C3 saved gets; C4 post-trigger requests of the table's k, unsupported or capped episodes), pairwise intersections and the union, so totals are not double counted.
- Example trace paths for every harm case (wrong binding, absent-made-present, OUT flip, C3 stale-risk get, C4 harm) and for each example class.
- An **Open search** section (patterns noticed besides the four candidates, counts and trace paths, unfiltered).
