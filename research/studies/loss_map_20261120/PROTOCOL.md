# Loss-map measurement of the current method: protocol (frozen 2026-11-20 before any measurement episode)

**Label: measurement for the idea search, no mechanism under test.** There is no hypothesis, no bar and no class (A-D) in this study. It measures where the current method (the steady loop, arm `FULL`) loses requests and answers on the development tasks, so that the next idea can be chosen from a map instead of from anecdotes. Development tasks only: nothing here is a held-out result and nothing here is evidence that any component works. Authorized by the owner's overnight instruction of 2026-11-19 (part C).

Preflight (AGENTS.md "Mandatory research context"): this is a measurement, not a proposal or an algorithm; no mechanism is implemented or tested. Closest prior work, read before writing: [candidate counts](../candidate_counts_20261118/REPORT.md) (offline counts (a)-(e) on 1,832 saved episodes, which did not classify requests above the floor and listed "serial single reads that could have been batched" as not examined), the thinking replication [REPORT_REPLICATION.md](../thinking_escalation_20261119/REPORT_REPLICATION.md) (FULL arm, seeds 3-4, same 18 tasks), and the closed stall-hint, finish-split and rendering studies (negative results preserved there). The decision this study can change: which failure or waste class has enough volume, spread over models and tasks, and enough room above the floor to justify a candidate mechanism next. Stop rule: one run of 288 episodes, one report; no repeat and no tuning of the classifier after the data are opened (section 5).

## 1. Design
- **System:** `FULL` of the thinking study's runner (`thinking_escalation_20261119/run_think.py`, pilot arm C1 unchanged, reasoning off, no per-request override), reached through the queue system id `LM-FULL` and the adapter `loss_map_20261120/run_lossmap.py`, which only adds the phase `lossmap` and otherwise re-exports that runner. gpt-oss cannot be switched off (its `false` is medium-like): its rows are reported but marked as in the replication.
- **Tasks (18):** development tasks as in the replication: stage 3 `u3 p3 h4 v2`; e1h `e1h_amb_1 e1h_amb_2 e1h_abs_1 e1h_abs_2 e1h_chg_1 e1h_chg_2`; name-fix `nf_single_1 nf_single_2 nf_multi_1 nf_multi_2 nf_amb_1 nf_amb_2 nf_exact nf_absent`. **Models (4):** `lfm3:1.7b`, `qwen3.5:9b`, `gpt-oss:20b`, `bonsai-2:4b` (digests in `FREEZE.json`). **Seeds 5, 6, 7, 8** (new: part A used 1-2, the replication 3-4). **18 x 4 x 4 = 288 episodes.**
- **Settings (as in the replication):** temperature 0.7, `num_ctx` 65536, `num_predict` 4096, 40 iterations, HTTP timeout 240 s, episode timeout 1,800 s, round-2 oracle with the 5 s retry, scorer v2.0 (`c6b02716152da0258b1296e7e6e0178d966c1c7c425f96e8c3f725bfd62b4ed9`).
- **Order:** the study's own frozen plan: 12 fixture sessions (model x environment), tasks and seeds shuffled inside each session (master seed 20261120, key `20261120-lossmap-<model>-<env>`). Plan SHA-256 `f477e3d7dfde5b4ac28cf0d8a98e303f8c1408f789cf407b7c2fa1d0c2f9800a`, stored in `exam_queue/specs/lossmap_spec.json`; the queue refuses to start if the plan differs.
- **Machine:** the laptop (RTX 4080 Laptop, 8 GB, Windows Ollama v0.40.16), one GPU job at a time. Queue run name `lossmap`. The GPU-state logging and the contention rule of `exam_queue/gpu_state.py` are active; under WSL `nvidia-smi` lists no processes, so rules (a) and (c) cannot fire there and a clean contention record is weaker evidence than on the lab (reported as such).
- **Smoke first (not in totals):** run `lossmap_smoke`, seed 99, `lfm3:1.7b`, tasks `u3` and `nf_single_1`, to check the adapter, the name-fix environment and the GPU-state block. A failed smoke is fixed and re-run before the measurement; it does not change any measurement setting.
- **No scenario or criterion is changed after seeing results.** Infrastructure failures (no model request, GPU contention by the frozen rule) are re-run by the queue; every other episode, including failures, stays in the results.

## 2. What is measured (descriptive only)
For every episode: supported-complete, exact, requests, tokens, native operations, ending class, and the **floor** of its task (`floor` in the task file: the number of model requests of the shortest correct route as the task builders defined it; the pilot records supported episodes at exactly the floor, for example 4 requests on a floor-4 task. Whether the floor counts the finish request is checked on saved traces and stated in the report). Requests above the floor of an episode = `max(0, requests - floor)`.

## 3. Classification (definitions frozen here; the code is `classify.py`, hashed before the measurement data are opened, section 5)
Each model request is labelled from its tool calls and results (parsed with `offline_replay_20261116/episodes.py`; a call's entity is the node/topic/service it names). **Every request above the floor and every unsupported episode is assigned one primary type**, in this precedence order, plus secondary flags:
1. **format / interface:** the request's calls were all rejected by the harness before reaching ROS (invalid arguments, tool not offered, finish-tool format, answer not accepted), or the request produced no tool call and no accepted answer (text only, empty), or the backend failed (error, length cut).
2. **identical repeat / loop:** a call with the same tool and the same arguments as an earlier call of the episode that already succeeded (a *repeat*); a *loop* is three or more consecutive requests whose calls are all repeats.
3. **name guessing and recovery:** a call whose entity is not in the episode's name ledger (names seen in task text and earlier results) and whose result is an error / not-found (*guess*); the request after it that obtains a name (a list or info call) or retries with a ledger name is *recovery*; a guessed name that later succeeds counts as a lucky guess and is flagged.
4. **serial / batchable read:** a request whose successful read calls only use entities that were already known (task text or results) before the *previous* request, so that they could have been sent in the previous request. (Reads that depend on the previous result are *necessary serial* and are not above-floor waste by themselves.)
5. **wrong conclusion with facts present** (episode level, unsupported episodes only): an answer exists and is wrong although every support fact of the task appears in the episode's tool results by the scorer's rule (candidate counts class D1); the strict count (fact literally present in a result) is also given.
6. **other:** everything else; examined by hand, with trace paths listed.

Unsupported episodes are classified by what the scorer reports plus the above: no answer (cap, timeout, backend error), wrong answer with facts present, wrong answer with a support fact never read (and why: name guessing, loop, format, stopped early), supported-but-not-exact. Tables: per model and per task, counts and share of the requests above the floor, with up to 3 example trace paths per cell (repo-relative). The report ends with an **Open search** section: other patterns seen in the traces, with counts and trace paths, unfiltered.

## 5. Analysis freeze
`classify.py` is developed on **existing development traces only** (FULL arms of part A and the replication, seeds 1-4, same tasks) while the measurement runs; its SHA-256 is written to `FREEZE_ANALYSIS.json` before any measurement trace is opened (only the queue's status counts are read during the run). After the data are opened the classifier is not changed; a defect found later is reported and fixed in a separate, labelled re-run, not silently.

## 6. Limits stated in advance
Development tasks only, 18 tasks, one environment family per task group; the same tasks and models were used for design, so no generalisation claim. Four models of different sizes: per-model counts rest on 72 episodes each and are not interchangeable. Counts are not independent samples (same tasks and fixtures across seeds). The classification is a detector (rules above), checked by hand reading on a sample, not a diagnosed cause. gpt-oss's thinking level cannot be controlled. Laptop only: no lab GPU stratum.
