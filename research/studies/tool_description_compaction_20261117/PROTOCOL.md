# Tool-description compaction test: frozen protocol (2026-11-17, before any episode)

Owner authorization (2026-11-17): write a short frozen protocol for a tool-description compaction test with an automatic, generic rule; arms FULL vs FULL + compaction on the same 40 cells (seed 1) shuffled in one session; primary: supported answers must not drop beyond noise (noise about +-4 cells; the bar is stated here before running); secondary: input tokens per request and per supported answer; count glob/regex and wrong-argument errors; freeze with a hash; run after the name-fix run has finished. Development tasks only, no held-out data, scorer v2.0 untouched, no push. Never overlaps a GPU job.

## 1. Question and mechanism
Question: can the model-visible description text of the 13 offered tools be shortened by a task-independent rule without losing supported answers? Why it could matter: the schemas are about 37% of all input tokens of the FULL arm (estimate, `steady_loop_ablation_20261117/FULL_ARM_MAP_TABLES.md`) and 41% of their characters are description text (`OFFLINE_SCHEMA_AND_REUSE.md`). Why it could hurt: the descriptions carry the information that `pattern` is a regular expression, which arguments exist and what they mean, so removing text may raise wrong-argument and regex errors. Prior closest evidence: the prompt change of Stage 3d lost correctness (`decisions/...ablation-protocol.md`, preflight); the 48-tool menu result shows that schema size changes behaviour (6 cells, not attributable). No novelty claim; shortening tool descriptions is ordinary practice and this tests one rule on one fixture family.

## 2. The rule (exact; implemented in `compaction.py`, hash in FREEZE.json; applied once to the original description of every offered tool)
1. Only `description` of the tool schema (openai format `{"type":"function","function":{name, description, parameters}}`) changes. `name` and `parameters` (argument names, types, required, defaults, enums) are copied unchanged.
2. Split the original description into HEAD = the lines before the first line that begins with a reST field marker (`:param`, `:arg`, `:argument`, `:key`, `:keyword`, `:type`, `:return`, `:returns`, `:rtype`, `:raises`, `:raise`, `:note`, `:notes`, `:example`, `:examples`) and FIELDS = each marker line with its continuation lines up to the next marker line.
3. TOOL LINE = the first sentence of HEAD, at most 160 characters.
4. For each argument name of `parameters.properties`, in schema order, that has a `:param <name>:` (or `:arg`, `:argument`) field (an optional type word between marker and name is allowed): ARGUMENT LINE = `<name>: ` + the first sentence of the field text, at most 100 characters. Arguments without such a field get no line.
5. New description = TOOL LINE, then one ARGUMENT LINE per line. Everything else (return and note fields, examples, second and later sentences) is dropped.
FIRST SENTENCE: collapse whitespace; the sentence ends at the first `.`, `!` or `?` followed by a space or the end of the text that does not end `e.g.`, `i.e.`, `etc.`, `vs.` or `cf.`; no such end = the whole text; if longer than the cap, cut at the last space at or before the cap (at the cap if there is none), appending nothing.
No tool names, no per-tool or per-task edits, no knowledge of the task or the fixture. Measured effect on the 12 domain tools: 2,056 -> 1,601 description characters (22% fewer; `measure_rule.py`); 47 tools: all names and parameters unchanged (test). Known losses by design: argument docs whose name is not an argument of the schema (e.g. `node_name` documented for the argument `nodes` of `ros2_node_info`), the `:note:` of `ros2_topic_echo` and the sentence "Valid range is 1-10".

## 3. Arms and design
- **FULL**: the steady loop C1 exactly as the ablation's fresh control (`steady_loop_ablation_20261117/ablation_arms.py`, arm FULL: 12 domain tools + final_answer, errors returned as text, strict pre-check, final_answer with one retry, observation-only guard). **COMPACT**: FULL with the rule above applied to the schemas offered to the model (`compaction_arm.CompactArm`); prompt, tool list, `parameters`, pre-check, execution and scoring identical.
- Cells: the ablation's 10 development tasks (u3, p3, h4, v2, e1h_amb_1, e1h_amb_2, e1h_abs_1, e1h_abs_2, e1h_chg_1, e1h_chg_2) x 4 models (lfm3:1.7b, qwen3.5:9b, gpt-oss:20b, bonsai-2:4b) x seed 1 = 40 cells x 2 arms = **80 episodes**; one fixture session per (model, environment) with both arms of its cells shuffled together (`random.Random(f"20261125-full-{model}-{env}")`); pair by cell. Smoke (2 episodes: qwen3.5:9b, u3, both arms) first, not in totals.
- Settings of the ablation: temperature 0.7, think false, num_ctx 65536, num_predict 4096, 40 iterations, 90 s HTTP and 900 s episode timeout, scorer v2.0 (`c6b02716...`), oracle with amendments 1, 2 and 4 (`run_round2.OracleWithRetry`). Oracle failure after its retry: the session's episodes are excluded as infrastructure and the session is rerun once; a second failure stops the run. All other valid episodes stay in the denominators (aborts, no answers, missed scripted changes). Stop at 4 h reserved wall time. Estimated cost: 80 episodes about 1.4 to 2 hours.
- Before the smoke: unit tests (payload: names, parameters, prompt, offered tools identical between arms; rule tests) must pass; code, fixtures, scorer, manifest, model digests are hashed in `FREEZE.json`.

## 4. Measures
Per arm, per model and paired by cell: supported (scorer v2.0) /40 and /10, transitions both / FULL only / COMPACT only / neither, requests, input and output tokens, **input tokens per request**, tokens per supported answer, requests per supported answer, aborts, no answers, cap hits, wall seconds. Errors (counted from the traces by `analyze_compaction.py`): **E1 regex/glob** = tool failures whose text is a regular-expression error (`multiple repeat`, `nothing to repeat`, `bad escape`, `unterminated`, `unbalanced parenthesis`, `bad character range`, `missing )`) plus calls to a list tool whose `pattern` contains `*` or `?` that is not preceded by `.`, `]` or `)` (glob style); **E2 wrong-argument** = strict pre-check rejections + stock validation errors + tool exceptions that are not regex errors; **E3 not found** = results with `Unable to find` (descriptive only). Exposure counts for these and the cells in which they occur are reported per arm.

## 5. Bars (fixed now, before any episode)
- **Primary (supported answers):** noise is taken as +-4 cells of 40 (the observed range of the control on these cells: pilot C1 35, fresh FULL 36, round 1 C1 32). **No drop beyond noise** = supported(COMPACT) >= supported(FULL) - 4. **Drop beyond noise (FAIL)** = supported(COMPACT) <= supported(FULL) - 5. A drop of 3 or 4 is reported as "within noise but a loss": every FULL-only cell is audited for a description-related chain (a wrong-argument or regex error in COMPACT that FULL did not make). No per-model bar (10 cells per model are too few); per-model results are descriptive.
- **Secondary (efficiency):** COMPACT is "worth keeping" only if (a) the primary bar is met, (b) mean input tokens per request is at least 3% lower and input tokens per supported answer is at least 3% lower than FULL (expected from the character count: about 115 to 160 tokens of a mean 3,400 per request = 3.4 to 4.7%, so this bar can fail on size alone), and (c) the error flag below is not raised. The 3% scale is a pragmatic screening scale, not a noise bound.
- **Error flag:** raised if COMPACT has at least 3 more E1+E2 events than FULL and at least 50% more. Then the shortened text is blamed for the extra errors whatever the supported counts are.
- **Verdict words:** primary met + (b) + (c) -> "eligible as an optional component for the Saturday freeze" (not "proven"); primary met but (b) or (c) not -> "no benefit shown / not eligible"; primary FAIL -> "do not use". One seed and 40 cells cannot show equivalence: "no drop" is not "no effect".

## 6. Report
REPORT.md with the usual five-row header, measured and interpretation kept apart, tokens and requests per arm first, the paired table, the error counts with the cells, hand reading of every discordant cell and of every E1/E2 event cell, and the loss list (which description text was removed from which tool).
