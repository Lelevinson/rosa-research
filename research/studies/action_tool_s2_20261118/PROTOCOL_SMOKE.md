# Action tool S2: tiny model smoke (frozen before the smoke code exists)

2026-11-18, Asia/Taipei. Purpose: check that a real small model can call the guarded `rotate_to_heading` tool against real turtlesim through the unchanged S1 executor, and that the post-action-state switch (off / on) works end to end. **Not a performance comparison**: 4 episodes cannot show whether the switch helps. Development only; not registered in ROSA or any harness (a stand-alone loop `smoke_loop.py` is used); turtlesim is a workbench, not a reported result. Authorisation: the owner's message of 2026-11-18 (S2 tests first; smoke only if they pass; one GPU/ROS job at a time; report before anything larger). Held-out files not opened.

## Design
- **Model:** `qwen3.5:9b` (Ollama on the Windows host), temperature 0.7, think false, num_ctx 65536, num_predict 4096, 12 iterations, 90 s HTTP and 300 s episode timeouts. Seed 1 is recorded as the order seed only (Ollama sampling is not seeded here).
- **Tools offered (identical in both arms, hashed):** `rotate_to_heading(theta)` (from `TURTLESIM_POLICY`, schema generated by `tool_schema`), `read_turtle_pose()` (read-only: returns `observe_state()` of the backend), `final_answer(answer)` (JSON object). One short system prompt, the same in both arms.
- **Arms:** `OFF` = `ExecutorOptions(attach_post_action_state=False)`; `ON` = `True`. Nothing else differs.
- **Tasks (2, designed by the author of this protocol, not blind to the method; fixed here):**
  - `A1`: "Turn the turtle so that it faces heading 1.5 radians, then reply with the heading it ended with as {\"heading\": <number>}."
  - `A2`: "Turn the turtle to heading 2.0 radians and then to heading -1.0 radians (in that order), then reply with its final heading as {\"heading\": <number>}."
  Each episode starts with a freshly started turtlesim (initial heading 0.0).
- **Episodes:** 2 tasks x 2 arms = 4, order shuffled with master seed 20261124. Policy: `TURTLESIM_POLICY` (goal budget 3, execution deadline 15 s).
- **Success (judge):** reported only, from an independent ground-truth reader (a separate rclpy subscription, after the episode, after the turtle has been still for 1 s): true final heading within 0.1 rad of the task's final target (angle difference), AND the answer's `heading` within 0.1 rad of the true final heading. This is not scorer v2.0 and not a statement about methods.

## Clean criteria (all must hold; otherwise stop and report, no larger run)
1. All 4 episodes end with a recorded ending (answer, cap of 12 iterations, or error); no crash of the loop or the executor; none over 300 s.
2. Arm fidelity from the logs: the serialized system prompt, user task text and tool schemas are byte-identical across the arms (hash); the line `State after action:` appears in tool results only in `ON` and only after a call that sent a goal; the executor events show the same decision rules in both arms.
3. Safety/accounting: every goal sent appears in the executor event log with a terminal state; no episode ends in `PENDING` or `ACTIVE`; the turtle is still (pose stable over 1 s) at the end; no `UNKNOWN_LOCKED` unless a deliberate test caused it (none planned).
4. Ollama loaded only `qwen3.5:9b` and it is unloaded afterwards; no other ROS/GPU job was running; turtlesim processes are all stopped afterwards.
A model failure (wrong heading, no answer, REJECTED calls) is an outcome, not a stop condition.

## Outputs
`PROTOCOL_SMOKE.md`, `PROTOCOL_SMOKE.sha256`, `smoke_loop.py`, `SMOKE_RESULTS.jsonl` (one row per episode with the executor events and the transcript path), `REPORT_S2.md`. No claim about the switch is made from 4 episodes; a larger run needs its own frozen protocol and the owner's decision.
