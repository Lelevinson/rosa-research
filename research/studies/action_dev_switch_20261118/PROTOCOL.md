# Turtlesim dev action tasks: post-action-state switch OFF vs ON (frozen before the loop, judge and analysis code exist)

Dated 2026-11-18, Asia/Taipei. **Development / targeted evidence only** (8 tasks written by the author of this protocol, who knows the method; synthetic turtlesim workbench; four small models; not held-out, not blind, not a result about original ROSA or about Nav2/TurtleBot3). Authorisation: the owner's message of 2026-11-18 ("action tasks are IN the paper"; design 8 dev turtlesim tasks, freeze, run switch off vs on, 4 models, seeds 1-2, nohup after a clean smoke; one GPU/ROS job at a time; report requests, tokens, success by independent ground-truth read, verification calls per episode). Held-out files are not opened. Scorer v2.0 is not involved (this is a different kind of task; success is the independent ground-truth judge below).

## 0. Preflight record (AGENTS.md)
- **Observed opportunity and evidence:** action tasks are in the paper (owner decision). S2 showed the guarded tool works end to end on real turtlesim (`action_tool_s2_20261118/REPORT_S2.md`); the offline write-attempt count shows small models (mostly bonsai) reach for write tools they were not asked to use, and that no write reached ROS under the guard (`write_tail_repeat_20261118`). Whether attaching the robot's own post-action state to the result lets models skip verification reads, or helps them, is untested beyond 4 smoke episodes.
- **Candidate vs control difference:** exactly one: `ExecutorOptions.attach_post_action_state` False (OFF, control) or True (ON): after any call that sent a goal, the result gets one extra line `State after action: heading <h> rad, position (<x>, <y>)` read from the robot's own pose topic. Prompt, tool schemas, executor policy, tasks and judge are identical.
- **Closest prior mechanisms:** (i) the smoke of S2 (4 episodes, no inference); (ii) result-side information such as pilot arm C1+FN and canonical rendering (class B, no benefit), which add or rearrange text in tool results. Known framing in robotics agents (reading state after acting) is common practice; "compare later (unverified)": ROS-LLM / RAI action wrappers. Not a novelty claim.
- **Fair evaluation and cost:** paired design (same model, task, seed, Ollama seed in both arms), 128 episodes, roughly 2 hours; turtlesim only. **Known validity limits:** tasks are authored with knowledge of the method; the dependent tasks R2 and M3 are designed so that the attached line carries information a model otherwise has to read with `read_turtle_pose` (this is the point of the targeted test and also what makes it favourable to ON: a favourable result here is **not** evidence that ON helps on tasks where the state is not needed).
- **Smallest decision-changing next action and stop rule:** this study. If the smoke is not clean, stop and report; do not start the full run.

## 1. Setup
- **Models (4):** `lfm3:1.7b`, `qwen3.5:9b`, `gpt-oss:20b`, `bonsai-2:4b` (digests recorded in `FREEZE.json`). Ollama on the Windows host; temperature 0.7, think false, num_ctx 65536, num_predict 4096, 15 iterations, 90 s HTTP timeout, 300 s episode timeout. Ollama `seed` = 1000 x run seed + task number, identical in both arms (sampling is not guaranteed reproducible).
- **Loop:** the stand-alone loop of the S2 smoke (`smoke_loop.py` lineage), `run_action_study.py`: system prompt "You control a simulated turtle in ROS 2 turtlesim. Use the tools to act and to look. Headings are in radians. When you are done, call final_answer with a JSON object."; tools offered in both arms (schemas hashed): `rotate_to_heading(theta)` (guarded: unchanged S1 executor + `TurtlesimBackend`, policy `TURTLESIM_POLICY`: theta in [-pi, pi], goal budget 3, execution deadline 15 s), `read_turtle_pose()` (read-only: the backend's `observe_state()` text), `get_parameter(node_name, parameter_name)` (read-only: `ros2 param get`, 10 s limit, returns its text or its error), `final_answer(answer)`. A fresh `turtlesim_node` (heading 0.0, position (5.54, 5.54), `background_r` 69) is started for every episode; the executor is new per episode.
- **Arms:** `OFF` (switch False), `ON` (True). **Seeds:** 1 and 2. **Episodes:** 8 tasks x 4 models x 2 seeds x 2 arms = **128** (64 per arm). One session per model, its 32 episodes shuffled (master seed 20261125), models in the order lfm3, qwen3.5, gpt-oss, bonsai; the previous model is unloaded (`keep_alive` 0) before the next loads.

## 2. Tasks (8; labelled dev / targeted; texts fixed here)
Answers are JSON objects through `final_answer`.
| id | kind | text | success requires (all) |
|---|---|---|---|
| S1 | single act | "Turn the turtle so that it faces heading 1.0 radians, then reply with the heading it ended with as {\"heading\": <number>}." | true final heading within 0.1 rad of 1.0; reported heading within 0.1 rad of the true heading |
| S2 | single act | same with -2.5 | same with -2.5 |
| S3 | single act, range trap | "Turn the turtle so that it faces 4.0 radians, then reply with the heading it ended with as {\"heading\": <number>}." (4.0 is outside the tool's range; the equivalent heading is -2.283) | true heading within 0.1 rad (angle difference, so equivalent angles count) of 4.0; reported heading within 0.1 of the true heading |
| R1 | act-then-read | "Read the parameter background_r of the node /turtlesim, then turn the turtle to a heading equal to that value divided by 100 (in radians). Reply with {\"background_r\": <number>, \"heading\": <number>}." | `background_r` equals 69; true heading within 0.1 of 0.69; reported heading within 0.1 of the true heading |
| R2 | act-then-read | "Turn the turtle so that it faces heading 1.2 radians, then reply with the turtle's position as {\"x\": <number>, \"y\": <number>}." | true heading within 0.1 of 1.2; reported x and y each within 0.1 of the true position |
| M1 | two-step act | "Turn the turtle to heading 0.5 radians, then to heading 2.8 radians (in that order). Reply with its final heading as {\"heading\": <number>}." | true heading within 0.1 of 2.8; reported heading within 0.1 of true |
| M2 | two-step act | same with -1.5 then 0.8 | target 0.8 |
| M3 | two-step act, relative | "Turn the turtle to heading 1.0 radians. Then turn it a further 1.5 radians counter-clockwise from where it ended up (a new absolute heading). Reply with its final heading as {\"heading\": <number>}." | true heading within 0.1 of 2.5; reported heading within 0.1 of true |
**Independent ground-truth read:** after the loop ends, a separate rclpy node reads `/turtle1/pose` twice 1 s apart (must differ by less than 0.01 rad: "still"); the second read is the true pose. The judge uses only the true pose, the answer, and for R1 the known parameter value 69. A model's own state reports are never used as truth. Angle differences are wrapped to [-pi, pi]. Heading-only goals leave the position unchanged by design.

## 3. Measures (per arm, per model, per task kind, pooled)
- **Success** (judge above) of 64 cells per arm; paired view per (task, model, seed): both / OFF only / ON only / neither (descriptive: trajectories diverge).
- **Model requests** and **input + output tokens** (Ollama `prompt_eval_count` + `eval_count` summed over requests).
- **Verification calls per episode:** `read_turtle_pose` and `get_parameter` calls are counted; **verification** = a `read_turtle_pose` call made after at least one rotate call that sent a goal (`goals_sent` >= 1) and before the final answer. Also reported: all `read_turtle_pose` calls, rotate calls, goals sent, and results by kind (SUCCEEDED, REJECTED with the check named, TIMEOUT, LOCKED, NOT_READY). For R2 a pose read after the action is needed under OFF (the task asks for the position), so verification is also reported separately for task kinds where the final answer needs only the heading (S1-S3, M1-M3), where an unneeded read is waste, and for R1/R2.
- **Endings:** final_answer, text answer, iteration cap, backend error (HTTP error of Ollama, including tool-call parse errors), timeout; capped = cap, backend error or timeout.
- **Safety/accounting:** executor final state per episode (TERMINAL / IDLE expected); any `UNKNOWN_LOCKED`; goals sent per episode (<= 3 by policy); the turtle still at the end; `turtlesim_node` processes after each episode (must be none).

## 4. Reading rule (frozen; conventions, not significance tests)
Detectability from the dev noise (power note `final_exam_draft_20261118`): with 64 cells per arm a difference in success below about 9 cells (14 points) and in mean per-cell request ratio below about 21% cannot be told from run-to-run noise. Pairs share a seed but trajectories diverge.
- **Signal V (verification):** mean verification calls per episode is at least 25% lower in ON than in OFF overall, **and** lower (not equal or higher) in at least 3 of 4 models.
- **Signal E (efficiency):** total requests at least 10% lower in ON overall, **and** lower in at least 3 of 4 models.
- **Harm flags (any):** ON success lower than OFF by 6 or more cells of 64; total tokens up by 10% or more; capped endings up by 3 or more episodes; any `UNKNOWN_LOCKED` or other safety anomaly in more ON than OFF episodes; or ON success lower in at least 3 of 4 models (each by 2 or more cells).
- **Classes:** A = V or E seen and no harm flag ("a possible method component for tasks where the state matters; establishes nothing until a blind, larger test"); B = neither seen and no harm flag ("no evidence of an effect in these cells"); C = a harm flag ("reported, not adopted"); D = V or E seen with a harm flag (both reported).
- Every statement is limited to these 8 authored tasks, 4 models, 2 seeds and turtlesim. No change to a prompt, schema, task text, judge, policy or the analysis after the first live request. Differences of up to about 9 cells in success cannot be distinguished from noise.

## 5. Smoke, clean criteria and stop rules
- **Smoke (not in any total):** `qwen3.5:9b`, tasks `S3`, `R1`, `R2`, seed 1, both arms = 6 episodes.
- **Clean means all of:** (1) every episode ends with a recorded ending and the judge ran (true pose read, still); no loop or executor crash; none over 300 s; (2) prompt, task text and tool schemas byte-identical across arms (hash); the `State after action:` line appears only in ON and only after a goal-sending call; (3) every goal sent has a terminal executor state; the executor state is not PENDING/ACTIVE/UNKNOWN_LOCKED at the end; the turtle is still; (4) `get_parameter` returned the real value for `background_r` in at least one R1 episode (tool path works); the judge agrees with a hand check of the 6 rows (reasons printed); (5) Ollama loaded only the expected model and it was unloaded; no `turtlesim_node` left; no other GPU/ROS job. A model failure (wrong answer, REJECTED calls, no answer) is an outcome, not a stop condition. Any harness, judge, oracle or fidelity anomaly: stop and report; do not start the full run.
- **Full run (only after a clean smoke, with `nohup`):** stop and report if Ollama is unreachable, if the simulator does not become ready in 3 consecutive episodes, if another job takes the GPU, or if a `turtlesim_node` remains after an episode and cannot be killed. Episodes with no model request (infrastructure) are listed and reported with and without; none is silently dropped or re-run under a changed rule.
