## Item 1. Compact-row crash window and log integrity (implemented in `queue_core_rev2.py`)
Defect of the frozen `queue_core.py` (reproduced by `tests_rev2/negative_control.py`): `Results.add()` fsyncs the full row, then serializes and appends the compact row, and marks the cell done only at the end. (a) A kill between the two appends leaves a full row without a compact row for good (12 full rows, 11 compact rows). (b) A failing compact append in a live runner raises after the full row is durable; the in-process recovery then appends a second full row (13 full rows for 12 cells).
Repair:
1. Encode both JSON lines before appending either.
2. Append the full row (fsync) and mark the cell done at once, then append the compact row. A compact append that fails (OSError) is logged and left to step 3; it cannot cause a second full row.
3. `reconcile()` runs at every start (after orphan cleanup and `recover()`), in the standalone `recover` command, before every dispatched episode **and before every exit of the runner (finished, stopped, failed)**. Every full row of this machine without a compact row gets its compact row from the same function and salt, from the durable full row, without rescoring and without re-running. The join is then checked: a compact row without a full row, a compact row that differs from the one rebuilt from its full row (except GPU fields) or two compact rows for one cell stop the run. Contended attempts are reconciled in order (one compact row per attempt).
4. **A write failure is never a success (blocker 3a).** If the compact table cannot be brought up to date, the run ends with state `integrity_error` and exit code 5, not `finished`. An integrity error during dispatch is re-raised; it is no longer handled by the generic block retry, which could quarantine the wrong cells.
5. Torn last line of an own log (full, compact, contended, starts, interrupted, **and the runner's `attempts.jsonl` in every block folder, blocker 3b**): the broken bytes are written to a new `<log>.torn_<UTC time>[_n]` file (never overwriting another copy), fsynced, and only then is the log cut back to the last complete line. A last line that is complete JSON but lacks its newline keeps the record. A broken line that is not the last line stops the run and changes nothing. A torn full row is re-logged by `recover()` from its attempt line and trace (no re-run). A torn attempt line means the worker's completion receipt is not durable: the attempt counts as interrupted (item 2). Another machine's log is only read.
6. Duplicate full rows of one cell: agreeing records (outcome and cost fields equal) are counted (`duplicate_full_rows_agreeing` in the start line) and the first record stays the result; disagreeing records stop the run. `merge-check` reports raw, conflicting and unlisted duplicates (`ACCEPTED_DUPLICATES.json`) and full rows without a compact row, and fails on any conflicting or unlisted duplicate or missing compact row.
7. Failure bookkeeping: the failures file is written atomically; one failed attempt is one failure (the frozen code counted the same attempt again at the end of every block and at every restart, because `recover()` re-logs unresolved attempts; found while testing D2 and fixed by counting each run folder once).

## Item 2. Crash re-run rule (final text; D2 and D3 applied; implemented in `queue_core_rev2.py`)
**Definitions.** An *attempt* is one launch of a worker for a cell. Durable (fsynced) records: the **start receipt** (queue, before the worker is launched) and the **close receipt** (queue, after the runner's worker function returned or raised), both in `STARTS_<machine>.jsonl`; the runner's own **attempt line** (`attempts.jsonl`, written after the worker exited); the **result** (the first full row of the cell). A *result* is never re-run, replaced or deleted.
**Interrupted attempt.** An attempt with a start receipt, no attempt line in any `attempts.jsonl` (a torn attempt line counts as missing), no result or contended row, and whose worker function did not merely raise (an exception the runner survives is an ordinary block failure). The durable completion boundary is the attempt line, not the worker's own files: a trace that already ends with `episode_end` but has no attempt line, no ending marker and no result is an interrupted attempt (the case found by Codex).
**Failed attempt after requests (D2).** An attempt that has an attempt line but no result (nonzero worker exit, missing ending marker, the bridge's failure branch) and whose trace shows at least one model request.
**Rule.**
1. An interrupted attempt or a failed attempt after requests is not a result. It is excluded from every analysis, kept on disk, and written once per run folder to `INTERRUPTED_<machine>.jsonl` (event `interrupted` or `failed_after_requests`, with the number of model requests seen and whether the trace had an `episode_end`).
2. **Which receipts decide and what the trace may say:** the receipts decide whether an attempt is interrupted; the trace's number of model requests decides which retry policy applies (rule 3 or 4); the content of an answer, a score or any outcome plays no role. The `episode_end` flag is recorded for the report and does not enter the decision.
3. An interrupted attempt with **no** model request, a failed attempt with no model request, and a GPU-contended attempt (its own frozen rule) keep the generic count: the cell is tried again until `quarantine_after` (3) failures. Zero-request interruptions are charged from the ledger (recomputed from the file at every start, so a crash between the ledger write and the charge loses nothing).
4. The cell with a first interrupted attempt or failed attempt **after model requests** is run again **once**, with the identical cell id and seed (a new sample is drawn and may differ). A **second** such attempt of the same cell (any mix of the two kinds) quarantines the cell: it is not started a third time, it is reported as skipped, the tier is "finished with skips", and its analysis is withheld until the owner decides how skipped cells are reported. A quarantined cell is never dropped silently.
5. Why this is allowed next to the rule that a cell that made a model request is not re-run: a re-run replaces nothing that was ever a result, the discarded attempt is kept and counted, and the decision cannot depend on the outcome. A crash can still correlate with episode length or failure; that is a limitation, and it is why the counts are reported with every result table: interrupted attempts, failed attempts after requests and quarantined cells, per system and per model, plus the ledger file.
6. The pre-start cells (run before this revision) have no start receipts and are not flagged (item 6).
Tests (dummy system, all pass): killed during the episode without `episode_end` (re-run once, one ledger entry); terminal trace without attempt line (same, `trace_had_episode_end` true); the discarded attempt stays on disk and is never a result; interruption before any model request (charged from the ledger, cell runs again); second interruption with requests (11 results, `finished_with_skips`, never started a third time); torn attempt receipt (repaired, evidence kept, the cell with the torn receipt is one ledger entry and one re-run); failed attempt after requests once (re-run, ledger, not charged to the generic count) and twice (quarantine); one interrupted plus one failed attempt (quarantine); failed attempt without requests (generic, two failures then success, no double counting); zero-request charge survives a lost failures file and is idempotent.

## Item 3. ROS discovery daemon (blocker 1; implemented in `queue_core_rev2.py`)
Defect: every `ros2 node list` without `--no-daemon` (the agent's tools use it) starts the domain's discovery daemon, `python3 -c "from ros2cli.daemon.daemonize import main; main()" --name ros2-daemon --ros-domain-id <domain> ...`. It outlives the worker and shows up as a hidden node `/_ros2cli_daemon_<domain>_<hash>` (visible with `ros2 node list -a`). The real static fixture rejects any extra node at its start (Codex). The frozen cleanup does not match its command line (checked: `health.ros_leftovers` finds nothing, with the episode-cleanup patterns and with `LEFTOVER_PATTERNS`).
**Does the frozen rev-1 path leave it, and does that break normal back-to-back episodes or only a crash?** Yes, it leaves it, and it is **not only after a crash**: in the dummy test with a strict start check modelled on Codex's description of the real static fixture, the frozen queue completed the first episode, left the daemon, and failed the second episode with no crash at all (`test_control_the_frozen_queue_leaves_the_daemon_and_the_second_episode_fails_without_any_crash`). What I could not check: whether the real runtime's own teardown stops the daemon in some cases (Codex observed that it did not after an E3 episode), and how the real static fixture counts nodes; the strictness of the check is Codex's report, not my reading of the code. In the real exam the first block would then fail from the second cell on, unless the daemon happened not to be started.
**Repair (candidate 3, hardened after CODEX_REVIEW.md 17:07):** `stop_run_daemon()` stops the run-owned daemon(s) **by PID only**: SIGTERM, a wait, then SIGKILL; the domain-wide `ros2 daemon stop` RPC is not used (the test forbids any subprocess call). Ownership must be **positive**: the command line is the daemon's, the environment has `ROS_DOMAIN_ID` equal to the runner's, `ROSA_EXAM_RUN` equal to `<run name>/<machine>` (the queue sets this marker at start; every worker, `ros2` command line and daemon of this run inherits it) and, when the runner has `ROS_HOME` (the launcher sets one bundle-wide home shared by run names), the same `ROS_HOME`. Without a marker or a domain nothing is matched, so domain-only or home-only matching is impossible; ownership is re-checked right before each signal. A **survivor gate** follows every stop: if an owned daemon is still alive after TERM and KILL, `DaemonSurvivorError` is raised: after an episode it blocks the next dispatch, at start-up it ends the run before any dispatch (exit 5), at the end of the run it replaces `finished` (state `integrity_error`, exit 5). Stops happen (a) after every episode in `episode_cleanup`, (b) at start-up after the orphan and fixture cleanup, (c) at the end of the run. A dummy test run uses it only when `ROSA_QUEUE_DAEMON_CLEANUP=1`.
**Risk to check on the real runtime (P6):** the marker only identifies a daemon if the real worker passes its environment on to the `ros2` command lines (the launcher uses `Popen` without an `env=` argument, so it should); a daemon without the marker is not stopped and is not reported as a survivor (the real static fixture would then refuse to start and the cell fails as infrastructure). Codex's isolated E3-to-static check through the actual entry point settles it.
Tests (domains 77 and 78 only, never 219, localhost only; **never run two test suites on domain 77 at the same time** - the frozen suite's cleanup kills ROS command lines of the domain and made six daemon tests fail when both ran together): the daemon is stopped after every episode and a static fixture (empty graph incl. hidden nodes, then a node created) starts afterwards; the control against the frozen queue (above); resume stops an owned surviving daemon (`discovery_daemons_stopped: 1`); a daemon of another domain is never touched; a daemon with no marker, with another run's marker or with another `ROS_HOME` is not signalled and no `ros2` command is run to stop one (`subprocess.run` forbidden); no marker or no domain matches nothing; **a daemon that survives TERM and KILL (signals swallowed by the test driver) blocks the next dispatch: exit 5, state `integrity_error`, one episode started, the first result kept, then a restart without the fault stops it by PID and finishes; and a survivor at start-up blocks before any dispatch.**

## Item 4. Partial-tier rule and interim looks (final text; D1 applied)
**Complete tier.** The frozen planner's cell ids of the tier (rebuilt from the spec and the pool) each have exactly one full row; no full row outside the plan; no quarantined or skipped cell; no duplicate full row outside `ACCEPTED_DUPLICATES.json`; and the machine's whole compact table joins the full log one to one: no missing compact row, no compact row twice, **no orphan compact row anywhere in the file (blocker 4: an orphan blocks every tier and is reported as `compact_rows_outside_plan`)**.
**Only a complete tier is analysed.** `analyze_when_complete.py` is the only way to run the primary comparison: it runs `integrity_look`, and only if the tier is COMPLETE it runs the frozen `analyze_primary.py` with `--planned-pairs` equal to the planned number of pairs; otherwise it prints "X of Y cells done; no comparison", exits with code 3 and computes and writes nothing. `analyze_primary.py` is never run by hand on an incomplete tier (it computes the comparison even when it labels it INTERIM, and with `--planned-pairs` set to the partial number it prints "FINAL ... PASS").
**Interim-look rule.**
- **Health checks: any time.** Queue status counts, heartbeat, Ollama version and digest guard, disk, GPU, ending-class counts, infrastructure counts, interrupted/failed-attempt counts (`integrity_look.py`, `status_stage1.py`). No trace, answer or task id.
- **Result looks: only at checkpoints**, i.e. the end of a seed within a tier and the end of a tier. **At a seed checkpoint the look is the integrity look only (D1).** The comparison (difference, token ratio, intervals, verdict) is computed once, by `analyze_when_complete.py`, when the tier is complete. Aggregate rows only; no held-out trace, answer or task text is read.
- **No change, stop or re-run decision may be based on a result look.** A stop is allowed for health reasons only (infrastructure share over the frozen flags, version or digest change, crash, disk, an owner decision unrelated to results), decided from health checks alone.
- **Interim seed checkpoints are never reported** (not to the team, not in a table, not in a message). Only the complete tier is reported.
`integrity_look.py` reads the compact table (system, model, ending, wall seconds), the full-log cell ids, the ledger, the failures file and the contended compact log. It merges `supported` and `unsupported` into `answered`, reads no trace and prints no outcome, token or request field (tested).
**Infrastructure (blocker 4):** the frozen analysis counts rows with ending `infrastructure` over the system's rows (`infrastructure_rows_in_compact_share`); the queue never turns an infrastructure failure into a row, so that figure is normally 0. `integrity_look` therefore also prints an `attempt_level` figure per system: GPU-contended attempts (their own log) plus zero-request attempts of the ledger, over rows plus those attempts. The frozen 5% and 10% flags remain defined on rows; the attempt-level figure is a diagnostic next to them (whether it should become a flag is a question for the owner and Codex).

## Item 5. Legacy full records of the two pre-start cells (blocker 2; implemented)
The four archived full records (two cells, each twice, duplicates agreeing) have no `model` and `seed`. `fill_legacy_fields()` recovers both **in memory** from the cell id `pool|task|system|model|seed` for reconciliation; the stored records are never rewritten. Every full row (old or new) is also checked against its cell id: a disagreement in pool, task, system, model or seed stops the run. The two existing compact rows are verified against the rows rebuilt this way and left as they are; the two agreeing duplicates are counted. Tests on copies of a completed dummy run turned into the legacy shape: both cells carried forward without `KeyError`, the archived lines byte-identical, compact file byte-identical, nothing started again, `merge-check` clean with the accepted list; a lost compact row of a legacy cell is rebuilt from the cell id; a row that disagrees with its cell id stops the run. **Not tested:** the real custody logs (Codex, P5).
