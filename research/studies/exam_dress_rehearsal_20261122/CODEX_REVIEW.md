## 2. Restart after a hard kill

**The real preflight does not refuse an occupied domain.** `queue_core.run()` calls the launcher-wrapped `load_spec()` first. `queue_bridge.backend()` verifies the runtime and hook hashes, then the real `fixtures.preflight()` calls only `files()`, which verifies the fixture index and dependency hashes. The launched fixtures use a startup liveness check. The strict rehearsal stand-in places an empty-domain check in its own preflight. That check accounts for the recorded strict restart refusal.

Keep the real hash checks in their current position. The smallest candidate change, if the real crash test exposes a survivor, is to make startup cleanup wait for the run's orphan process groups, inspect the survivor list now ignored by `run()`, and verify a clean isolated domain before recovery or dispatch. The existing cleanup uses command-line patterns for the domain sweep and cannot establish graph emptiness by itself. Any new domain check belongs after cleanup. No ordering patch is needed to fix the stand-in refusal in the real runtime.

There is a distinct crash-recovery defect. `Results.add()` fsyncs the full row before it serializes and fsyncs the compact row. On restart `read_done()` reads the full log alone, and `recover()` skips those cells. A crash between the two writes reproduces a full-only result even with the revision-1 metadata repair. For rev 2, the bounded repair is to validate compact serialization before either append and reconcile missing compact rows by salted cell key from the durable full records before dispatch, without rescoring them. Verify that a public-dev interruption between those writes gives exactly one full and one compact row and no re-execution. Keep historical duplicates as incident evidence and account for them explicitly in the merge audit. No fix was applied.

## 6. Rev-2 draft and release decision

1. **Crash-window repair.** Keep the durable full record as the recovery source. Encode both JSON records before either append. After a successful full append, a compact-write failure must not leave the same live runner free to append a duplicate full record during its in-process recovery. On startup and standalone recovery, reconcile the current machine's missing compact rows from the full log using the original run salt and metadata, and verify the join before dispatch. Define how to detect and preserve evidence of a torn final JSONL record and how to stop on conflicting duplicates. Test an interruption between appends, a second restart, and a compact-write failure that triggers in-process recovery. The pre-start duplicates should stay in the incident record and be accounted for explicitly.
2. **Crash reruns.** The proposed `no episode_end` condition misses one of the two dev interruptions. One interrupted trace already has `episode_end` but has no ending marker, attempt ledger or result row. The other has no `episode_end`. Both had model requests. Define a durable completion boundary and the recovery action for each case, including a terminal trace without a completed attempt receipt. Reconcile this exception with the existing rule against rerunning cells that made a model request. A once-only exception needs durable per-cell accounting. The current generic retry is not that accounting.
3. **Partial tiers and interim looks.** Make seed checkpoints integrity-only. Check actual planned cell membership and uniqueness for the tier, including quarantines, before permitting comparisons. For an incomplete tier, use counts and infrastructure logs. `analyze_primary.py` computes comparisons even when it labels the output INTERIM, so citing only its invalidation section would still compute the prohibited comparison.
4. **Version guard and prior cells.** A read-only snapshot of the Windows setting returned `auto_update_enabled=0`. The live, metadata-only revision-1 verifier passed the file hashes, all seven model digests and the recorded Ollama version. No guard was started for this audit. The launch script currently starts the runner before opening the guard window. If guard readiness is a precondition, establish it before dispatch. Also define how to flag a provider change that overlaps a recorded outcome. An episode with a model request can receive a durable backend-error or timeout row and need not be retried by the current queue. Carry forward the two completed cells once each. Decide the analysis treatment of their revision cohort explicitly before the next result look.
5. **Apply procedure.** The revision-aware verifier should check each overlay against its predecessor and reject unknown changes. Assign the final readiness review after the repair and public fault-injection checks to avoid a precondition that requires a ready verdict before its own repair can be made.

**Not ready for rev-2 freeze.** The real binding, fixture lifecycle and public bridge check passed. The outstanding blockers are the implementation and fault-injection proof of full-to-compact recovery, the approved crash-rerun and interim-look rules, and the final freeze and carry-forward accounting. No frozen code, draft or exam result was edited and Stage 1 was not started.
