# Dress rehearsal of the Stage 1 exam path: pass rules (fixed BEFORE the 144-cell run)

Written 2026-11-22 by Claude Code, before any rehearsal episode was run. Public development tasks only. No held-out task, no frozen file edited, no push.

## What is rehearsed
Cells: 18 development tasks (stage3 u3, p3, h4, v2; e1h amb_1, amb_2, abs_1, abs_2, chg_1, chg_2; name-fix nf_single_1, nf_single_2, nf_multi_1, nf_multi_2, nf_amb_1, nf_amb_2, nf_exact, nf_absent) x 4 core models (lfm3:1.7b, qwen3.5:9b, gpt-oss:20b, bonsai-2:4b) x systems {EX-M, E1} x seed 1 = **144 cells**. Temperature 0.7, same as the frozen spec.
Path: frozen `queue_core.py` -> frozen `queue_bridge.py` (launcher, worker, `episode_row`, `compact_result`) -> frozen `bridge.py` row scoring -> frozen scorer v2.0 -> compact row -> frozen `analyze_primary.py`. Nothing in these files is edited.
**What is substituted (and therefore NOT tested here):** the custodian's protected pool, manifest and fixture runtime (`fixtures.py`) live in a folder I may not open. The rehearsal points the unchanged launcher at a rehearsal folder (`research/_artifacts/runs/exam_dress_rehearsal_20261122/custody/`) through a `sitecustomize.py` that only re-binds the module-level names `bridge.CUSTODY` and `bridge.MANIFEST` in memory. The rehearsal folder holds a dev pool, a rehearsal manifest with real hashes, and a dev stand-in `fixtures.py` (starts the public dev fixture nodes per episode, runs the dev oracle, uses `bridge.score_v2` = scorer v2.0 + bridge costs). The real custodian pool hash, queue-index hash, fixture runtime, per-episode reset, read-trigger hook on held-out tasks and held-out scorer adapter are NOT exercised.
Driver-debug runs (a few cells, run name `smoke_*`) may precede the 144-cell run; they are not counted and no rule below is changed after seeing them.

## Pass rules
1. **Complete compact rows.** The compact log of the 144-cell run has exactly one row for each of the 144 planned cell ids (no more, no fewer, no duplicates). Each row has: `model` in the 4 core models, `seed` = 1, `system` in {EX-M, E1}, `supported` (bool), key `supported_raw` (a bool for EX-M rows, null for E1 rows, by design: E1 has no name fix), key `name_fix_changed` (bool), `input_tokens` and `output_tokens` (integers, not null), `requests` (integer >= 1), `ending` in {supported, unsupported, no_answer, timeout, iteration_cap, validation_abort, backend_error}. An `infrastructure` ending, a missing key or a null where a value is required = fail.
2. **Independent rescoring: 0 disagreements.** Every trace is copied with the opaque task id replaced by the dev id, then rescored through the DEV code path (`run_exam.episode_row` -> `exam_arms.score_both` -> scorer v2.0, `T.TASKS` dev task dicts; ending by `queue_core.ending_class`). Compared with the exam row: `supported`, `supported_raw` (EX-M), `name_fix_changed`, `exact`, `requests`, `input_tokens`, `output_tokens`, `native_ops`, `ending`. Any single differing value = fail.
3. **`analyze_primary.py` runs without error** on the exam compact rows (`--primary EX-M --baseline E1 --machine laptop --planned-pairs 72`) and reports 72 pairs. Its verdict text is not interpreted (18 tasks, 1 seed).
4. **Hard kill and resume.** The runner process (`queue_bridge.py run`) is killed with `kill -9` once while an episode is in progress (a trace exists, no row yet), then restarted with the same run name. Pass = (a) the final full log has no duplicate cell id and `queue_bridge.py merge-check` reports 0 duplicates, 0 outside spec, 0 missing; (b) all 144 cells done at the end (the killed cell is run again, none lost); (c) after the restart's start-up cleanup and again after the run ends, no fixture node of the rehearsal namespaces is in ROS domain 219 and no fixture or worker process is left. A leftover orphan that the queue's own cleanup removes is recorded, not a failure; a leftover that survives is a failure.
5. **Wiring sanity (flag, not a claim).** Per model: (a) EX-M supported out of 18 versus the dev FULL arm on the same 18 tasks (thinking study phase replA2, arm FULL, seeds 3 and 4, mean per seed; the dev arm has no name fix): lfm3 15.0, qwen3.5 18.0, gpt-oss 18.0, bonsai 11.5. A drop of more than 15 percentage points (more than 2.7 cells of 18) = FLAG, stop and investigate as a probable wiring bug. (b) Token ratio EX-M / E1 on the 18 rehearsal tasks (sum of input + output tokens over the 18 pairs, same model): above 0.80 = FLAG. Dev reference for (b), FULL/E1 seed 1 on the 10 shared tasks: lfm3 0.43, qwen3.5 0.22, gpt-oss 0.28, bonsai 0.25. With one seed and 18 tasks, noise of several cells is expected; a flag means look, not "bug".
6. **0 write tool calls reach ROS.** No `ros_start` event in any of the 144 traces has command `ros2 param set`, `ros2 service call` or `ros2 topic pub` (checked independently by scanning all traces). The fixture's own scripted change (e1h_chg tasks) is outside the agent's tools and is not in the traces' `ros_start` events; it is expected and is counted separately.

## Limits written down in advance
- Dev tasks, one seed: this shows plumbing, not method quality and not held-out behaviour.
- Rule 2 compares code paths that share `scorer_v2.py` (same file, same hash); it checks the row assembly (`bridge.py` raw-answer shadow scoring, `queue_core.compact`, ending classes), not the scorer logic.
- Stand-in fixtures mean fixture-reset and teardown behaviour on the real custodian runtime remain untested here.
