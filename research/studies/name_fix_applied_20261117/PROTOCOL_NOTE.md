# Name-fix applied test: dated implementation note and freeze (2026-11-17)

Design (frozen by the owner, unedited): `research/decisions/2026-11-17-name-fix-applied-test.md`, SHA-256 `1e5d05213b3982a15ef65dfb8d1ac916dd8a403ed68ebeb5cbcf51230e8874a0`. This note adds only what the design leaves to the implementation and the owner's approval of 2026-11-17 for the collision revision. Everything here was written before any model episode.

## 1. Rule revision (owner-approved, new dated rule; not the round-2 rewrite)
`namefix_rule.py`, `RULE_NAME = "name-rewrite-v2 (collision-safe), 2026-11-17"`. Identical to the round-2 rewrite (verified equal output on every collision-free case in `tests/test_namefix.py`) except: (1) **objects**: if a rewritten key would equal the candidate of another key of the same object, every key of that group stays unchanged and `collision` is logged; (2) **lists** (owner's addition): if rewriting a list item would duplicate another item in the same list, the rewritten items of that group stay unchanged and `collision` is logged. Nothing is ever overwritten, merged or dropped. The control of the design ("same rule in shadow, submits the original") is realized as the pairing within each episode: the original answer is kept in the trace (`final_answer_original`) and scored beside the submitted one; there is no separate off-arm.
Collision preflight: `PREFLIGHT_COLLISION.md` (the exact round-2 rule FAILED, 3 of 3 cases lost a value silently; rule v2 PASS, 0 values lost in 7 cases).

## 2. Development set (8 designed stress cases; built from the public E1h/Stage 3 templates only; no held-out definition opened)
`namefix_build.py` (seed 20261124, own word list, namespace `/nf`, 20 nodes) -> `namefix_graph.json`, `namefix_tasks.json`. Tasks: `nf_single_1` (publisher of a topic), `nf_single_2` (subscriber of a topic), `nf_multi_1` (three subscribers, node names as nested keys, gains as values), `nf_multi_2` (two input topics of a node as nested keys, their publishers as values), `nf_amb_1`, `nf_amb_2` (two nodes with the same base name in different namespaces: the short name is ambiguous), `nf_exact` (full name given, answer repeats it), `nf_absent` (asks for `/<ns>/<node>`, not running; `/nf/<ns>/<node>` is running: the known suffix-repair harm mode; the name asked for is in the task text and therefore an exact ledger name that the rule must leave unchanged). The fixture has unique suffixes (single, multi tasks) and colliding suffixes (amb tasks). No answer map or name list is given to the model. Verification (`namefix_fixture.py check`, run before any model call, `check_*` folder): the minimal route of every task, executed with the real ROSA tools, reproduces the truth answer, is scored supported by scorer v2.0 and has the floor of the task (2 or 3 requests); the oracle matches the graph.

## 3. Scoring
**Strict (primary):** scorer v2.0 unchanged (SHA-256 `c6b02716...`); `namefix_scoring.score_events/episode_scores` only choose which answer object (original or submitted) is scored on the same rows; the new tasks use the same `answer`/`support` format as the E1h tasks, so no translation of rules is needed. Positive and negative fixtures (`tests/test_namefix.py`, 8 tasks x truth / extra key / missing key / no answer / no evidence; short names rejected). **Lenient (secondary):** `namefix_scoring.lenient_transform` as defined in the design: relative whole-segment suffix of the required name that is unique among graph names of the same kind, only at positions where the required identity is a graph name; then the same `v2.score_task`. Frozen negatives: ambiguous short name, wrong entity, absolute partial name, extra key, absent-task name, wrong values, missing evidence. The graph is evaluator-only.

## 4. Run
64 episodes = 8 tasks x 4 models (lfm3:1.7b, qwen3.5:9b, gpt-oss:20b, bonsai-2:4b) x seeds 1, 2; one session per model, 16 cells shuffled with master seed 20261122 (`run_namefix.py`). Pilot settings (temperature 0.7, think false, num_ctx 65536, num_predict 4096, 40 iterations, same observation-only guard), amended oracle (`run_round2.OracleWithRetry`, amendment 4), C1 base with gate/nudge/list/sweep/rewrite-shadow off. Smoke (not in totals): qwen3.5:9b, nf_single_1, nf_multi_1, nf_amb_1, nf_absent, seed 1. Stop rules as the ablation (oracle failure after retry: the stopped session's episodes are excluded as infrastructure and the session is rerun once; second failure stops the run). No result is looked at before the run ends; no rule above changes afterwards.

## 5. Bars (verbatim from the design)
**Safety FAIL:** even one originally strict-supported answer becomes unsupported, a wrong-identity rewrite, or a key collision/overwrite (an overwrite = a value lost; a logged `collision` that leaves everything unchanged is not an overwrite). **Eligible for consideration:** zero such harms among the actually rewritten answers, at least 8 episodes with an actual rewrite across at least 2 models and 2 distinct task templates, and at least 2 strict unsupported->supported episodes with independently verified correct identity and complete evidence. Otherwise **INCONCLUSIVE / NOT SHOWN**. Reports: four cells for every planned episode (strict original/applied, lenient original/applied) with the paired transition counts, no-answer and aborts (denominator 64), emitted answers, rewritten episodes and fields, eligible shorthand, ambiguous/unseen/collision cases, wrong-identity rewrites, task/model slices; harmful rewrites / answers actually rewritten and supported->unsupported / originally supported answers actually rewritten (unavailable if the denominator is zero); every changed answer, strict improvement and support loss audited against fixture truth and evidence (`audit` in the report), not the rewriter's ledger; unchanged exact full-name answers reported too.
