## 1. F: Forge queue adapter
Files (`research/studies/exam_arms_20261121/`): `forge_episode.py` (runs under the Forge interpreter, imports `episode()` from the frozen `forge_baseline_20261115/run_full.py` and calls it unchanged), `run_forge.py` (queue hooks `run_worker`, `episode_row`, `load_env`; system id `F` in `exam_queue/systems.py`), tests `tests/test_run_forge.py` (5, on a saved gate episode in `tests/forge_fixture/`). The interpreter comes from `ROSA_FORGE_PYTHON` (**updated later on 2026-11-21: default `~/.local/share/rosa-exam/forge-env/bin/python`, persistent and outside the repository, see `final_exam_draft_20261118/freeze_package_20261121/FORGE_ENV.md`**; it was `/tmp/rosa-forge-env-20261121` when the smoke runs below were made; forge-guardrails 0.10.1, created by `uv venv ... --python 3.12` and `uv pip install forge-guardrails==0.10.1`); a missing interpreter stops with the creation command, there is no fallback.
**What is unchanged from the pilot:** the episode function (12 C1 read tools + released `respond`, C1 system messages with `final_answer` -> `respond`, matched transport with the pilot's explicit `think` field, 40-call budget, 90 s HTTP timeout, temperature 0.7, `num_ctx` 65536, `num_predict` 4096, seed), the frozen scorer v2.0 on the trace, the 900 s episode timeout.
**Differences, recorded:**
1. **Oracle retry.** The pilot's own driver (`run_full.session`) stops with a RuntimeError on an oracle mismatch and retries only a CLI timeout (3 attempts, no wait). In the queue, `run_pilot.session` runs with `run_round2.OracleWithRetry` (daemon read, 5 s retry), the same rule as every other arm. This is the "oracle retry the pilot runner lacks", provided by the queue instead of by editing the frozen runner. The 2026-11-21 smoke gate showed the pilot driver stopping at an `after` oracle check on a discovery flake.
2. **Session driver:** fixtures, `before`/`after` oracle and cleanup are the queue's (`run_pilot.session`), not `run_full.session`'s.
3. **Log location:** the episode function appends a transport-check line to a file in the runner's folder; the worker points that folder at the block directory, so the frozen pilot folder is not written to.
4. **Token accounting:** the pilot's `append_result` summed `usage` with a default of 0 for missing fields. The adapter reads each `wire_response`: a request without usage (non-200 or no `prompt_eval_count`) has `null` in `usage_per_request`, is counted in `usage_missing_requests`, and `token_totals_lower_bound` is true when any exists. Totals are sums over known usage.
5. **Ending class:** `MaxIterationsError` in the Forge error is mapped to the phrase "iteration limit" so the queue classes it as `iteration_cap`. Forge's own `_ToolCallExhausted` (three failed tool-call attempts) is not mapped and falls into `backend_error` today (open: whether it needs its own row).
**Queue smoke (qwen3.5:9b, tasks p3, u3, e1h_amb_1, seed 1; run `baseline_smoke_F_20261121`):** 3 of 3 episodes done, 0 skipped; supported 1 of 3 (p3 yes; u3 and e1h_amb_1 no); requests 5, 6, 6; usage missing 0; GPU state `ok`, not contended. Three episodes say nothing about Forge's quality (the same model and task u3 was supported in the earlier gate; one sampled run each).

## 4. Held-out routing: what the bridge can and cannot serve today
Read: `custodian_stage1_20261121/README.md` and `queue_bridge.py` (code and interface documentation only; no pool, index or task file; I did not run the bridge). At the time of reading the committed bridge (8b48a56) accepts only `SYSTEMS = {S0, E1, EX-M, EX-NO_MENU, EX-NO_FINISH, EX-NO_ERRORTEXT}` and `run`/`recover` refuse any other system, so **the draft spec's tier 2 (F, MT) cannot execute held-out cells through it**. Its worker `episode()` is hard-wired to an in-process `PilotROSA` + `ArmTracedModel` loop inside the private fixture session.
- **MT needs one change on the custodian side:** add `"MT"` to `SYSTEMS`. `episode()` already builds any other arm with `exam_arms.make_arm`, and that function now returns the MT arm (stock executor, same `PilotROSA` path as S0). I did not edit the custodian file.
- **F cannot be served by that loop.** What F needs: (a) the episode runs in the Forge interpreter (`forge_episode.py`), so the custodian worker module and its private-fixture imports must be importable from that interpreter, or the worker must run in the project interpreter and start Forge as a child that talks to the fixture; (b) the request text must come from the bridge (`user_message(opaque_id)`), but the pilot's `episode()` reads the request from the development task table, so held-out F needs a **parameterised copy of the 70-line episode body** (identical loop, request and fixture start supplied by the bridge): that is a real, recordable deviation from "unchanged pilot function"; (c) native reads must be reported to the fixture (`observe`) as they complete, via the guarded-native wrapper the episode already installs; (d) the trace format the private scorer reads must carry `tool_start`/`tool_end`, `ros_start`, `model_start`, and per-request usage with nulls kept (the bridge's `episode_metrics` sums `model_end` usage and cannot see missing usage); (e) the bridge `ending` file (`iteration_cap`, `backend_error`, ...) must be computed for Forge errors.
- **Codex's uncommitted `ExternalRunner` (README section "External runner contract", `external_runner.py`, in progress while I worked) appears to be the interface meant for this:** `heldout(episode_dir)`, `user_message(opaque_id)`, `fixture(...)` hooks `observe_native` / `observe_tools`, `score(...)`; it mentions Forge `wire_response` and lower-bound tokens. I did not build held-out workers on it because it was uncommitted and changing, the instruction limits today to public dev tasks, and wiring a worker into the launcher means editing custodian files. **Next step for Codex or the owner:** commit the interface, add `MT` to `SYSTEMS`, decide how a Forge worker is launched, then I can write the two held-out workers and smoke them on the 2 public dev cases.
The "smoke through the bridge with its 2 public dev cases" was therefore **not run** for either system.
