## 1. The renderer (rules R1-R8, frozen text; code follows this text)
Input: one tool result object. Output: a rendered object of the same shape.
- **R1 containers.** dict values and list items are visited recursively; keys, numbers, booleans, null and the container shape are unchanged. Only string leaves are rendered.
- **R2 line classes (the generic parser).** Split a string leaf on `\n` (a trailing `\r` is ignored). A line is **blank** if it has only whitespace; otherwise let `s` be the line with leading and trailing whitespace removed. If `s` contains the two characters `: ` (colon, space), it is a **key-value line**: key = text before the first `: ` (stripped, must be non-empty), value = text after it (stripped). Else if `s` ends with `:` and has other characters, it is a **header line** (a section). Else it is a **bare line**. A line whose leading whitespace contains a tab is a bare line. No class depends on any key text.
- **R3 structure.** The indentation of a line is its count of leading spaces. Depth comes from an indentation stack: pop while the top is greater than the indentation; if the stack is empty or its top is smaller, push; depth = stack size - 1. A **block** is a maximal run of consecutive key-value lines with the same indentation, with no blank, header or bare line between them.
- **R4 render condition.** A string leaf is rendered only if it contains at least one key-value or header line. Otherwise it is returned byte-identical (pass-through).
- **R5 rendering.** Drop blank lines. Write each remaining line as `2 * depth` spaces plus `s`. Keep a trailing `\n` if the original had one.
- **R6 name resolution (ROS 2 semantics).** In a block, if exactly one key equals `P + "namespace"` and exactly one key equals `P + "name"` for the same prefix `P` (`P` may be empty; matching is on the exact lowercase words, or the exact capitalised words `Namespace` / `Name`), and the namespace value starts with `/` and the name value is non-empty and does not start with `/`, then insert one line directly after the later of the two lines, at the same depth: `P + "full name": <full>` (when `P` is empty the key is `Full name`), where `<full>` = namespace without trailing `/`, then `/`, then name (namespace `/` gives `/name`). If the block already contains that key, or has more than one namespace or name key for that prefix, nothing is added. The original two lines stay.
- **R7 typed values.** There is no typed-value rule. A line such as `Integer value is: 74` is only a key-value line (key `Integer value is`, value `74`) and is rendered as it is.
- **R8 errors.** Rendering is applied only to results that are not harness messages; error dicts and not-found texts contain no key-value line (or are rendered like any text) and must come out equal under the lossless check.
Anything not covered (lists of names, bare names, JSON numbers, free text, log lines without `: `) passes through unchanged. **No rule may mention a tool name, a field name other than the words `name` and `namespace`, a fixture, or a task.**

## 3. Measurements and bars
1. **Lossless (bar).** For every result, with `L(x)` = the non-blank lines of the string leaves, each with whitespace runs collapsed to one space: (a) the sequence `L(original)` is a subsequence of `L(rendered)`, in order; (b) every line in `L(rendered)` that is not matched to an original line is a derived full-name line, and for each such line an independent check finds, in the original leaf, a namespace line and a name line with a common prefix whose values join to exactly that full name; (c) non-string leaves, keys and container shape are equal; (d) rendering twice equals rendering once. **Bar: 0 results with a lost or changed fact (violation of a-c).** (d) and the number of results changed byte-for-byte are reported.
2. **Scorer invariance (bar).** Re-score every population episode with scorer v2.0 after replacing each rendered result in the trace events by its rendering. **Bar: 0 episodes change `supported_complete`, `exact` or `support_missing`.** (This shows a live arm can be scored by the unchanged scorer without extra credit from derived lines.) Episodes that fail to score for a reason unrelated to rendering are listed.
3. **Size change.** Per result: characters of `json.dumps(output, ensure_ascii=False)` before and after, per tool and per model; summary median, mean, minimum, maximum, share of results larger, equal, smaller. Estimated tokens = characters / 4 (an estimate, not a tokenizer count; the live run measures real tokens). **Per-episode history effect:** a result entering after request `r` is carried in the input of every later request, so the estimated input-token change of an episode = sum over its results of (characters change / 4) x (number of requests after `r`); reported per episode, per model, per study, and as a percentage of the logged input tokens of the same episode. No bar.
4. **Parsed vs passed through.** Per tool and overall: share of string leaves rendered (R4) vs passed through; share of non-blank lines that are key-value, header, bare; share of characters in rendered leaves; results whose rendering is byte-identical to the original; derived lines added (count and per tool); R6 skips by reason (already present, ambiguous block, namespace not absolute, name absolute). No bar.
5. **Name-fire analysis (reported).** For every fire of `candidate_counts_20261118` (a): the resolution `R` is classed, in this order, as **in the task text** (contiguous), **contiguous in an earlier successful result** (a `NAME_IN_TEXT` match or a node-list entry), or **split-only** (not contiguous anywhere before the fire, present in the ledger only as the join of a namespace field and a name field). For the split-only fires: how many of them contain, in the renderer output of the earlier results, the full name as a contiguous string (expected: all), how many typed names equal the value of the `name` field of the block that yields `R`, and how many differ. Per model and per study. This counts a **precondition** for the mechanism, not an effect of rendering: the recorded models did not see the rendered text.
6. **Temptation log.** Every moment while designing and writing the renderer when a tool-specific, field-specific or fixture-specific rule suggested itself is listed in `TEMPTATIONS.md` with what it would have done; none is added.

## 4. Reading rules
Bar 1 and bar 2 must both be met (0 violations) for the live protocol (step 2) to be run. If either fails, the report lists every violation with the trace path, the renderer is not patched, and no live run follows from this study. Meeting the bars shows that the rendering is lossless on the recorded results and does not change scoring; it does not show that models read it better, that it saves requests, or that the size change is acceptable (item 3 is a cost to be weighed in the live run).
