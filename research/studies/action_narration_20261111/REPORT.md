# ROSA action-turn narration: bounded causal investigation

11 November 2026, Asia/Taipei. **Stop this candidate branch. No algorithmic
contribution or quality-preserving general improvement is established.**

Twelve frozen A/B/C episodes and three activation episodes ran on actual local
Ollama and disposable ROS 2 Jazzy applications. The static terse controls reduced
generation cost on two supported Turtlesim tasks, but both lost support on the
recovery task that the ordinary control answered correctly. A separate runtime
context limit truncated every larger cross-application task. Final inventory
closure also failed. These failures remain in the evidence; this is a completed
bounded investigation with **incomplete protocol closeout**, not a validated
positive benchmark.

The dynamic D proposal was rejected **before implementation**: its normal/error
instruction switch has no supported behavioral capability beyond C's static
conditional instruction. This is a scoped design judgment, not proof that all
framework-level algorithms are impossible.

## 2. Actual controls, invocation and prior-art challenge

All arms use the same8 original read-only ROSA tool schemas: node/topic/service
list/info and parameter list/get. This common safety restriction differs from the
historical47-tool full registry, so no historical/new causal comparison is made.
Original wrappers retain their output forms; a shared shape-checked shell=False
backend records native stdout/stderr/status and bounds retries. No service calls,
parameter writes, task-to-source maps or evaluator information enter the agent.

A copies the ordinary ROSA prompt, **removes the complete known sequential-only
block**, and enables independent reads/list arguments while preserving dependencies
and answer obligations. B adds fixed terse tool-action guidance. C adds the static
exception permitting short repair narration after errors. Exact text is in
cases.json and every configuration.json. No global prompt list is mutated.

`episode` uses the same create_tool_calling_agent/AgentExecutor machinery as ROSA,
through its supported asynchronous execution path rather than the historical
synchronous wrapper. Native tool IDs and scratchpad observations remain LangChain's;
the measurement wrapper returns the original assistant message. Intermediate
actions preserve actual tool_call_id/observations. Separate UUIDs in wrapper/native
journals are receipt IDs, not those LangChain IDs. Identical simultaneous wrapper
calls may need multiset rather than one-to-one receipt matching; no unsupported
one-to-one causal join is claimed.

## 6. Decision, remaining uncertainty and review package

**Q1:** There is a local ordinary-prompt savings signal on two supported tasks,
but the complete quality-preserving hypothesis fails its stage1 gate here.
**Q2:** D is not admitted; C already describes its proposed behavior, and neither
static terse control preserves the recovery answer. No D implementation, candidate
stage, held-out set, fifth arm, extra repeat or provider/context retuning follows.
**Q3:** No meaningful new framework-level algorithm is justified by this evidence.
Keep the executable systems/negative findings without calling reduced incomplete
answers an optimization. A larger-context replication is a possible separately
frozen diagnostic, not an achieved repair or automatically selected next algorithm.

Limits: four reused development tasks, one seed each, two stock applications,
read-only subset, one host/model and provider default context; incomplete inventory
closeout; selected source snapshot; manual support judgment and no population
guarantee. The result neither certifies terseness universally harmful nor proves
all status-conditioned framework policies impossible.
