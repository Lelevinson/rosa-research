# GPT integration, factual coverage and framework admission

11 November 2026, Asia/Taipei. **The old unsupported-clock failure was not reproduced
in this bounded, context-corrected comparison. An unavoidable factual efficiency/
coverage trade-off is not established. No new framework algorithm is promoted.**

GPT-6 Luna was verified through the existing rosa-llm ChatGPT-plan OAuth provider
and the actual ROSA executor. Ten predeclared scored episodes ran, plus one native
activation episode per provider. All 10 final answers have acquired support for
all 92 requested scalar fields. Strict task completion is7/10: A 4/4, B 2/4, V 1/2,
because three otherwise factual answers violate the requested initial-check order.
All new protocol closeout checks passed. Earlier failures and conditional results
are retained without retrospective repair.

The decisive research distinction is between **source-supported facts**, **ordered
task execution**, and **framework guarantees**. A successful model can supply the
first two; current ROSA does not independently certify them. That acceptance gap is
real, but a new checker needs information and a cost advantage beyond ordinary
verification prompting, a fixed validator or ordinary ordered dispatch.

## 6. Critical framework assessment and concrete rules

See [ALGORITHM_ASSESSMENT.md](ALGORITHM_ASSESSMENT.md) for independent multi-pass
source/literature review and counterexamples. Root review also checked original
[ReAct](https://arxiv.org/abs/2210.03629),
[CRITIC](https://arxiv.org/abs/2305.11738), and
[ALCE](https://aclanthology.org/2023.emnlp-main.398/) records. These establish adjacent
reasoning/action, tool-feedback correction and attribution mechanisms, not replicated
ROSA gains. Related work is not a veto; the required increment is a different,
useful, fully charged choice under the same information.

Concrete generic candidate to challenge:

1. The model declares requested obligations and a proposed answer/claim binding to
   actual request-local receipts; include ordered dependencies where needed.
2. Framework checks receipt/call identity, observed success, exact path/span existence,
   declared subject/argument binding, time scope and unresolved obligations. Reject
   nonexistent links, pending/failed receipts and undeclared execution-order violations.
3. If unresolved, return a bounded repair request with missing structural evidence;
   otherwise render or admit the answer without an additional semantic review only
   when a trusted contract actually supports that admission.

This would reject **honestly declared** missing-clock obligations in the old B/C
trace. It does not guarantee that the model declared every obligation, chose the
right semantic source, bound the correct subject or supplied an entailing span.
A model can omit an obligation, cite a valid unrelated false value, confuse observed
and configured data or give an incomplete inventory. Public tool success, a valid
receipt ID and valid JSON do not solve those semantic cases. Framework metadata
does not independently encode arbitrary user-request completeness.

The strongest ordinary competitors must receive the same manifest, receipts and
contracts: a **fixed final validator** can make the same reject/repair decisions;
full-transcript tool-backed verification can check semantic gaps at additional cost;
generic source bindings plus a fixed renderer can avoid a final model turn when a
complete trusted answer layout already exists. Repackaging these as dynamic
admission is not yet an incremental algorithm.

For the newly observed order defect, every initial assistant proposal in04/05/07
lists stale node-info before topic-info. **Ordinary serial dispatch in proposal
order** would structurally enforce completion-before-next for that fixed batch,
without an application map or extra model turn. This is an unexecuted conditional
counterfactual, not a repaired episode or measured latency saving. It sacrifices
some native concurrency; its cost must be charged. A generic declared dependency
graph can preserve independent concurrency, but that is already an ordinary DAG/
LLMCompiler-style control, and an omitted model-declared edge remains a failure.

A potentially meaningful increment would select which semantic checks or barriers
to pay for using a calibrated public signal, beat the equally capable fixed
checker/serial/DAG controls in total cost, and preserve requested facts/procedures
on counterexamples. No such reliable acceptance/abstention signal or incremental
benefit is established here. Status-only normal/error switching is insufficient,
as the old normal-stop unsupported answers already showed. The old Round27/28
compiler/gate coverage losses remain relevant warnings, not proof all future
semantic contracts are impossible.

**Decision:** retain evidence receipts and model-declared obligations as an
engineering hypothesis; full algorithm implementation remains **BLOCKED / NOT YET
JUSTIFIED** at the incremental-discriminator gate. Do not silently substitute manual
application semantic maps or benchmark oracle fields to make it pass.

## 7. What the experiment answers, and what it cannot

- **Model limitations:** the old failure is not an unavoidable inability to acquire
  the facts: both current backends acquire all requested values in every arm here.
  This does not isolate a model-weights cause or prove the old model universally
  adequate. Current model/provider defaults and adapter changes are explicit.
- **Prompting:** prompt/backend combinations change calls, prose, repeated reads and
  ordering. LunaA needs no narration suppression; ordinary LunaV repairs the observed
  B order issue in one sample. QwenV does not. No universal prompt remedy is shown.
- **Framework:** unconstrained final acceptance and proposed-call scheduling leave
  coverage/order enforcement to the model. These are real boundaries, but the
  observed defect and a plausible guard do not themselves establish a new algorithm
  or a net-efficiency opportunity beyond strong ordinary controls.

The bounded discriminating mission is complete. No extra GPT inference, retuned
prompt, speculative full algorithm, new model substitution or broad benchmark was
run after seeing outcomes. Further work needs a specific distinguishable signal
and hostile-control case, not another name or generic audit.

Limitations:2 reused tasks,one observation/cell,2 providers,one local host/read-only
fixture,provider-managed Luna controls,manual semantic adjudication and no statistical
noninferiority proof. No physical robot, graph-churn generalization, arbitrary-tool
semantic guarantee or isolated causal decomposition of historical failures is claimed.
