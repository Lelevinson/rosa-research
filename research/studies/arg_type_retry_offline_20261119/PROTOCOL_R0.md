# Argument-type retry requests and a lossless schema-generic conversion: offline protocol (frozen before any number is computed)

Dated 2026-11-19, Asia/Taipei. Source: the owner's request of 2026-11-19, step 5 ("offline only: retry requests caused by argument-type errors that a lossless, schema-generic conversion would fix, e.g. an empty string where an array is expected; no live run"), and the ChatGPT review's mechanism 1 (`blacklist: ""` to `[]`; "first count distinct episodes and actual retry requests it could affect; if exposure is sparse keep it as an executor fix and give the strong control the same fix"). CPU only (`nice`), saved traces only, no Ollama, no ROS, no held-out files, scorer v2.0 untouched. Development evidence only; every number is a prediction from recorded traces, not a measured effect of a conversion.

## 0. Preflight record
1. **Observed opportunity.** Recorded argument-type failures: the fairness study's E0 arm had 49 `validation_text` write-tool attempts in the write-tail report (43 a dict or string `request` rejected by the stock schema) and S0/A1 ended 8 episodes on a validation error; the nudge run's FULL/NUDGE arms had strict pre-check rejections in 18 of 160 episodes (gpt-oss 16). This study counts all such events over all saved traces.
2. **Candidate vs control.** Candidate: before dispatch, convert an argument whose type is wrong in a way that has exactly one lossless reading under the tool's own JSON schema, run the tool, and return its normal result (no new tool, no new syntax, no hint). Control: the existing behaviour (the strict pre-check returns an error text and the model retries; in the stock executor the same, or the episode ends). The strongest ordinary control is the same conversion applied inside the stock executor too (so it is an executor fix, not a method difference); the study therefore reports stock and menu arms separately.
3. **Closest prior mechanisms.** The harness's own strict pre-check (`harness.py strict_error`, "no value repair", by design); the repair helper `h2_repair` of the pilot (arm family H2, different rule: repairs entity names); schema-guided argument coercion in function-calling stacks (unverified; not checked against original sources). The incremental claim is only that a lossless type conversion saves the retry requests the error causes; not a novelty claim.
4. **Fair evaluation and cost.** Offline replay over the saved traces; counts of events, fixable events, and the upper bound on requests (and tokens) that a conversion would have made unnecessary; harm check (lossless by construction plus a list of cases where the reading is not unique). No live run.
5. **Next action and stop rule.** One offline count. If exposure is sparse (section 4), the conversion is recorded as an executor-level fix to be given to every arm equally and nothing else is run. A live test is not proposed here.

## 1. Data
The 1,832 episodes of `candidate_counts_20261118` (`count_candidates.load_population()`), all arms and studies, parsed from `trace.jsonl` events directly: `model_start` (the tool schemas offered on that request, `schemas`), `model_end` (the response and its `tool_calls`), `tool_start` / `tool_end`. Per request: its calls are the `tool_calls` of its `model_end`. The tool schema used to judge a call is the one in the `model_start` of the same request. Reported by arm group: **menu arms** (12-tool menu, the strict pre-check; `FULL`-type and variants) and **stock-executor arms** (S0, A1, E0, E1: stock executor, 47 tools), per model, and for the FULL-type subset (`count_candidates.FULL_TYPE`).

## 2. Event and conversion (frozen)
- **Argument-type error event:** a call (name and `args` of a `tool_calls` entry) that fails the **strict check** `harness.schema_problems(args, schema, "")` (the C1 harness checker, unchanged), where `schema` is that tool's `parameters` from the same request's `model_start.schemas`. Each problem is (field path, expected type or "required field" or "one of ...", received value). Calls of `final_answer` are included; write tools (`ros2_param_set`, `ros2_service_call`) are included in the counts but reported separately and are **never** counted as fixable (the study conversion applies to read tools only).
- **Conversions (lossless by construction, schema-generic; each acts on one problem):**
  - **K1** a string where the schema expects `array` or `object`, if `json.loads` of the string yields a value of the expected type;
  - **K2** a scalar where the schema expects `array` and the array's `items` schema accepts that scalar: wrap it in a one-element array;
  - **K3** an empty string or `null` where the schema expects `array` and the field is **not** in the schema's `required` list: replace by `[]` (the "exclude nothing" reading; for a required field the reading is not unique and no conversion is made);
  - **K4** a string that parses exactly to an integer (`"12"`, no sign or space tricks, `str(int(s)) == s`) or number where the schema expects `integer` or `number`;
  - **K5** the string `"true"` or `"false"` (case-insensitive) where the schema expects `boolean`;
  - **K6** a float with an integer value (`3.0`) where the schema expects `integer`.
  Excluded on purpose (reported as "not convertible"): a dict or object where the schema expects `string` (the dominant stock `request` error: no unique reading), a number or boolean where `string` is expected, a missing required field, a wrong enum value, a wrong key, an array where a scalar is expected, anything else.
- **Fixable event:** every problem of the call is fixed by one of K1-K6 **and** the converted arguments pass the strict check again (`harness.schema_problems` returns nothing) **and** the call is not a write tool. The conversion is applied to the whole call; a call with one unfixable problem is not fixable.
- Received values in saved strict-check messages are truncated at 80 characters, but this study reads the full arguments from `tool_calls`, so truncation does not affect it.

## 3. Measures (frozen)
1. **Events** per tool, per problem kind, per model, per arm group; **distinct episodes** with at least one event; share of all episodes.
2. **Fixable** events and episodes by conversion (K1-K6), and not-convertible events by reason.
3. **Consequence of the original error** (from the same trace): for menu arms, whether the call was rejected by the pre-check (`validation_error` handler event for that tool and arguments) and for stock-executor arms what the stock executor did (an error text returned to the model, or the episode ended on the error: `episode_end` follows the failing request without a later `model_start`).
4. **Retry request (upper bound on saving).** For a fixable event in request `r`, its **retry request** is the first later request `r' > r` that contains a call to the same tool whose arguments are exactly the converted arguments of that call. A **pure retry request** is a request all of whose calls are such exact retries of earlier fixable events; a **mixed** one has some other calls. **Saved-max requests** = number of pure retry requests (upper bound: assumes the model would not have issued them; the model might have acted differently on a result that arrived earlier); mixed ones are counted separately and not as saved. **Tokens saved-max** = recorded input + output tokens of the pure retry requests. For stock-executor arms where an event **ended the episode**, also count the episodes that ended that way and are fixable (what the answer would have been is unknown).
5. **Lossless check:** for every fixable event, the converted arguments are logged next to the original and re-validated; a unit test covers each conversion and each exclusion. Cases where one problem has two plausible readings (K3 for optional fields whose default is not an empty array; unknown from the schema alone) are listed: for each tool with a K3-converted field, the schema default is reported.
6. Distinct **episodes affected** by fixable events, with the model and the arm.

## 4. Bar (frozen; exposure bar, not an effect bar)
- **Not sparse (a live test may be proposed to the owner):** over the **menu arms of the FULL-type subset**, saved-max requests are at least 1% of those requests **and** at least 10 distinct episodes over at least 2 models have a fixable event.
- **Sparse:** otherwise the conversion is recorded as an executor-level fix that every arm should receive equally (a plumbing fix, not a method difference), and no live test is proposed.
- Whatever the bar says, the counts, the per-tool table and every fixable event's original and converted arguments are reported. A result carried by one tool (largest tool share above 60% of fixable events) is flagged as not general.
- Statements are limited to these saved traces, tasks and models.
