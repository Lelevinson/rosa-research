# CPAW prototype: implementation and evaluation

## Decision

Retain this as an isolated research prototype, not as a ROSA optimization or novel algorithm. The logical certificate and generic executor seam work under explicit trusted-contract and snapshot assumptions. In synthetic small instances the revised policy makes some different wave decisions, but its benefit does not consistently survive comparison with exact fixed batching and exact adaptive waves. Current default ROSA registry eligibility is **0/47**. Do not begin full ROSA/LLM integration on this evidence.

## What was built

[cpaw.py](cpaw.py) implements generic Goal/Probe/Registration/Evidence/Plan contracts, validated executor-origin evidence, certificate logic, resource conflicts, wave limits, trusted read-only/concurrency controls, and an injected executor/fallback seam. It never parses raw CLI output, changes arguments, infers a tool equivalence, maps a question to a tool, or calls an LLM. Executor callback exceptions become UNKNOWN observations; invalid evidence terminates unresolved. Invalid plans invoke a caller-provided ordinary execution fallback. The seam is research code, not integrated with ROSA. A trusted bulk binding is represented as an explicit exact proposition set with work, duration and actual operation count; no source substitution or bulk capability is inferred. This is a synthetic accounting model, not a verified ROSA bulk implementation.

An exact exponential Bellman solver supports arbitrary finite joint T/F/U distributions and legal waves. Exact singleton DP supplies a strong classical adaptive k-of-n reference under independent binary/additive assumptions. The experiment also includes fixed-two and full legal batch, immediate adaptive greedy, exhaustive best fixed nominal batching, exhaustive minimax fixed batching, exhaustive minimax fixed singleton permutation, and the exact adaptive wave solver. The exact fixed nominal schedule dominates any feasible fixed schedule **in its own model's expected cost**, including a feasible realization of the Tan–Xu–Nagarajan construction; this is not an implementation of that paper. The exhaustive robust singleton permutation solves the finite-scenario fixed-order minimax problem, but is not the approximation algorithm or full interval uncertainty set in Tan–Nagarajan. Neither paper's performance guarantee is claimed. Exact references are exponential and available only for small instances.

CPAW enumerates a bounded deterministic set of legal candidate waves and uses finite-scenario bounded rollout with a strong fixed minimax continuation. The corrected policy chooses a shared continuation across still-plausible scenarios and admits a candidate only if its estimated advantage over the reference exceeds a margin in **every** modeled scenario. Cold starts, impossible observations, and exhausted computation budget fall back to the reference wave. The execution seam independently preserves ordinary dispatch for ineligible plans. Selection and fallback do not establish that the natural-language intent was interpreted correctly.

## Mathematics and restrictions

For n declared propositions, t observed TRUE, u UNKNOWN and r unattempted, the implementation returns TRUE iff `t >= k`, FALSE iff `t + u + r < k`, and UNRESOLVED when no attempts remain and neither certificate holds. These rules follow by assigning every U/unattempted proposition both possible Boolean values; exhaustive partial-state testing checks the proof for n=3 and all k. Evidence and unattempted IDs are retained. A certificate says nothing about missing requested facts, the correctness of the model's target/source/goal selection, or changes in the world. Snapshot identity is an assertion by a trusted external executor; matching timestamps or an arbitrary matching string do not prove a physically consistent state. No independent LLM task-completeness score is possible in these synthetic runs.

DP uses the model's conditional distribution of full outcome vectors, so correlation is representable when actually provided. The experimental nominal and sensitivity scenarios are independent products. Interval coverage of marginals does **not** establish joint coverage, robustness to dependence, or correct probabilities. The online robust lookahead uses a nested maximum over finite scenarios, a rectangular relaxation when depth exceeds one; with the tested depth one it evaluates one current wave plus a shared fixed continuation. This is not a distribution-free theorem or a guarantee that fallback cannot lose. Bounded candidate enumeration, conditional zero-probability states, calibration drift and incomplete scenario coverage all limit it. Time and node checks are cooperative; a single underlying enumeration, dispatcher, or reference callback is not preempted, so this is not a hard real-time implementation. On a budget expiration, evidence already collected remains available, and the result is unresolved when needed.

## Counterexamples and correction

[21 tests](artifacts/tests_final.txt) cover all 13 Section D categories, including branch-contrasting k=2/4, exhaustive certificate truth assignments, malformed plans and evidence, no opaque parsing, UNKNOWN, invalid snapshots, conflict/read-only/concurrency rules, trusted per-argument authorization, new generic registration and cold-start fallback, zero computation and execution budgets, synthetic inference and bulk-operation accounting, setup extremes, and invalid costs. The independent-intent and inference examples are deliberately illustrative, not a claim of real natural-language scoring or measured LLM timing. The native bulk test uses an explicit synthetic trusted binding; real bulk semantics remain untested. The first test run caught an opaque input raising `AttributeError` rather than a controlled validation error; the [failure](artifacts/tests_initial.txt) and subsequent correction are retained.

More substantially, [the original rollout](artifacts/cpaw_initial.py) calculated a different best continuation for each uncertainty scenario. That effectively lets it know which scenario is true. A regression witness has two remaining ANY probes with p=(0.9,0.1) versus p=(0.1,0.9): the per-scenario oracle continuation costs 1.1 in each scenario, but every single shared order has worst-case expected cost 1.9. The revised algorithm chooses one common minimax continuation and applies a paired scenario-wise margin. A later security review also found that a general tool authorization did not authorize individual argument bindings; a trusted per-argument callback is now required, and the identical experiment was rerun. The prior results are preserved under [pre_argument_authorization](artifacts/pre_argument_authorization/). The [original known-model run](artifacts/initial_run/) and [calibrated pre-control run](artifacts/calibrated_pre_control/) are preserved. An independent replay checked all 720 final constrained action logs, cost accounting and certificates with zero discrepancies. This checks declared-goal soundness, not external intent or semantic correctness.

## Controlled results

The final constrained experiment has 5 synthetic families × 12 instances × 12 arms = **720 episodes**, with the same sampled world per arm. All 720 certificates were sound relative to declared evidence; **24 were unresolved**, distributed across the UNKNOWN cases. Each calibrated instance has 64 prior simulated training vectors, also stored in the logs; these are an additional data acquisition cost, not free ROSA history. The cold-start arm receives an empty scenario set and a fixed model-free reference, with no training episodes charged or available to that policy: it fell back on 109/109 decisions across 60 episodes. An earlier cold arm accidentally used a calibrated reference; those results are preserved in [pre_cold_fix](artifacts/pre_cold_fix/). An initial run used generator probabilities directly and is labeled known-model, not calibrated. The 95%-target simultaneous Hoeffding marginal intervals contained all 12 true coordinates in 12/12 instances for each stationary family; the deliberately shifted family was covered in 0/12. Correlated data had correct-looking marginal coverage despite a wrong product dependence model. The finite three-scenario set is a sensitivity sample, not the full confidence region.

The following are mean composite cost per episode **including measured Python scheduler and preparation time** converted at 0.25 cost units/s. Native work and synthetic wave duration otherwise use the frozen fixture model. Twelve tasks per family are too few for a reliable population estimate; these are descriptive paired results, not significance claims. Raw logs provide native work, operation counts, simulated wave time, modeled inference time, fallbacks, attempts, and planner time separately. No real ROSA end-to-end timing or LLM speedup was measured.

## ROSA inspection and generalization

The actual ROSA 2 `ROSATools` registry contains 30 calculation, 13 ROS 2, 3 system and 1 log tool. All 47 have output schemas with only titles and no informative typed proposition output. `ROSATools` exposes no independent per-tool TRI_STATE_V1, read-only, or argument-level authorization registration. The instrumentation thus counts **0/47 eligible**, grouped in [registry.json](artifacts/registry.json); it never invokes a tool. Its optional separately trusted registration input is tested with an independently authored synthetic tool; tool-provided metadata alone is not authority. This static count reflects available registration capability; a real request would still require argument-level authorization. The observed denominator is the default registry's tool count, not representative task invocations, all user extensions, or an intention-to-treat task fraction. Prompt-inferred goal errors, actual eligible tasks, live executor safety, and LLM output fidelity were not measured. Existing ordinary ROSA behavior remains the fallback; no existing tool was modified.

## Novelty and next stage

Short-circuiting, outcome-contingent k-of-n ordering, robust intervals, staged batches, and conditional planning are established mechanisms. [Tan, Xu and Nagarajan](https://optimization-online.org/2024/07/a-general-framework-for-sequential-batch-testing/) already study adaptive and fixed batch testing; [Tan and Nagarajan](https://arxiv.org/abs/2603.23705) study distributionally robust fixed-order k-of-n testing. The present composition adds typed evidence, explicit UNKNOWN, a shared-continuation guard and a generic execution boundary, but the experiments establish neither a new mathematical result nor a robust performance advantage. The original scenario-clairvoyance bug was implementation-related; the corrected method's dependence on limited models, overhead and pre-existing fixed/adaptive competitors are algorithmic limitations, and the current absence of trusted contracts is a framework eligibility limitation.

Next, keep ROSA integration stopped unless independently authored tool contracts and trusted, stable-snapshot/permission capabilities become available without application-specific benchmark mappings. First strengthen evaluation with prospective, disjoint tool families; real contract validation and observed acquisition/latency cost; calibrated joint dependence; task-level eligibility and independent intent/completeness scoring; and the same strong controls. If that cannot be demonstrated, retain this work as a negative/bounded engineering result rather than inventing adapters or claiming general framework gains.
