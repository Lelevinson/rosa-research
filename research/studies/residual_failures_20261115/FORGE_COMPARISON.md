## Reading key and execution paths

Every Forge link below is pinned to the reviewed commit. **Similar** means a shared mechanism with an explicit implementation difference; **absent** means absent from C1 at the inspected integration points; **ours-only** means present here but absent from the compared Forge core path, not a claim of global novelty. No row is classified **same**: that stronger claim is unnecessary and unsupported for the complete mechanisms inspected.

Our loop is still a LangChain agent loop. `run_pilot.PilotROSA._get_agent` wraps registered ROSA tools using `Arm.wrap_tools`; `ArmTracedModel._generate` calls `Arm.visible_schemas` before each Ollama request; `PilotTool._parse_input` checks arguments before dispatch; `Arm.execute` applies availability guards and calls the underlying tool; LangChain appends observations; `PilotExecutor._get_tool_return` recognizes an accepted final answer. See [run_pilot.py:61–113](../small_model_harness_20261115/run_pilot.py#L61) and [harness.py:142–165](../small_model_harness_20261115/harness.py#L142).

Forge's `WorkflowRunner.run` creates a validator, step enforcer, and error tracker, calls `run_inference` for parsing/retries/compaction, checks workflow constraints, executes tools, then checks termination. **Runner, middleware, and proxy are different entry points**; the main table compares the runner unless stated otherwise. See [`WorkflowRunner.run`](https://github.com/antoinezambelli/forge/blob/8871a3c1a7dcf46f6bb70ebade55b1d30bd3936c/src/forge/core/runner.py#L138).

## Which parts need a predefined workflow?

**Required-step completion** needs a supplied list of tools that every valid solution must have successfully called before termination. Open-ended robot questions do not automatically provide that list. Imposing one fixed route across unrelated questions would be an extra task assumption; the static comparison does not establish it as available. Moreover, Forge's requirement is tool-name coverage, not fact coverage: a successful call with irrelevant arguments may satisfy a name-only requirement.

**Prerequisites** need supplied tool dependencies, optionally sharing an argument value. These can be general tool contracts rather than per-question scripts, so they are not inherently unavailable for open-ended questions. Their validity must be justified: ROS parameter reads, for example, do not universally require a prior node-list call. Forge does not discover these dependencies from robot questions. Both mechanisms inspect prior successful execution, not whether the resulting answer is supported. Sources: `StepTracker.is_satisfied`, `check_prerequisites`, `StepEnforcer.check`, and `check_prerequisites` cited above.

**Rescue parsing, name/container checks, retry nudges, runtime recovery, respond, compaction, context warnings, hardware budgeting and total iteration limits do not need a predefined answer route.** The runner still requires a `Workflow` object as configuration, but can use `required_steps=[]` with no prerequisites. A declared terminal response tool is a termination contract, not a pre-solved answer/source map. H7 is also distinct: its route is generated by the model, with the limitations described above.

## Entry-point differences that affect a fair Forge comparator

- **WorkflowRunner:** owns tool execution, runtime-error recovery, required steps/prerequisites, and the supplied context manager. `respond` must be registered and selected as terminal by the caller. These are the primary comparison paths above.
- **Guardrails middleware:** [`guardrails/guardrails.py`, `Guardrails.__init__`, `check`, `record:77–188`](https://github.com/antoinezambelli/forge/blob/8871a3c1a7dcf46f6bb70ebade55b1d30bd3936c/src/forge/guardrails/guardrails.py#L77) exposes validation, retry accounting and required-step blocking to another loop. This facade has no prerequisite configuration/check call and no public runtime-failure recording method; `record` records successes and resets counters. The host must execute tools and emit corrective messages. It is not the full runner automatically transplanted into ROSA.
- **Proxy:** [`proxy/handler.py`, `handle_request:483–515`](https://github.com/antoinezambelli/forge/blob/8871a3c1a7dcf46f6bb70ebade55b1d30bd3936c/src/forge/proxy/handler.py#L483) creates fresh validation budgets per request, calls shared inference with `NoCompact`, and does not execute tools or enforce a multi-turn workflow. On exhausted `ToolCallError`, it returns the last raw response as ordinary text, leaving the client's loop to decide what happens. Synthetic `respond` injection is **opt-in, default false**, at [`handle_request:265,436–448`](https://github.com/antoinezambelli/forge/blob/8871a3c1a7dcf46f6bb70ebade55b1d30bd3936c/src/forge/proxy/handler.py#L265). Comments or older README wording describing automatic injection do not override this default.

Thus “Forge as released” requires recording a release artifact/tag, entry point, tools, context strategy, terminal contract and budget settings. This report pins source behavior but does not claim that choosing one entry point evaluates all the others.
