## Results

1. **Initial pose, configured Nav2 lifecycle and short goal: PASS.** The installed `turtlebot3_world.launch.py` spawns at x=-2.0, y=-0.5, yaw=0; [navigate_once.py](navigate_once.py) publishes that initial pose in `map`. The installed map had 0 (free) at 11 centerline samples from spawn to the goal (-1.5, -0.5), resolution 0.05 m. The last run reported initial AMCL (-2.005, -0.503). All 12 configured lifecycle nodes reported `active`: map_server, amcl, controller_server, smoother_server, planner_server, route_server, behavior_server, velocity_smoother, collision_monitor, bt_navigator, waypoint_follower and docking_server. `NavigateToPose` accepted the goal and returned status 4 (`SUCCEEDED`). Last odometry x=0.259 m, y=0.001 m relative to start; success reflects Nav2's configured goal tolerance and is not proof of exact 0.5 m displacement. An earlier run also returned success but checked only nine lifecycle nodes. No physical robot was involved.
2. **Owned-process cleanup: PASS in tested cases; clean shutdown FAIL.** [stack.py](stack.py) starts a unique marked supervisor, checks domain 219 for pre-existing nodes, starts server-only Gazebo and Nav2, and `stop` first signals its own launchers, then escalates remaining marked processes to SIGTERM and SIGKILL, checking `/proc` after each phase. It refuses to start while its previous marked processes remain and reports failure if marked processes remain after escalation. A test dummy that ignored SIGINT and SIGTERM was killed by SIGKILL while an unmarked sentinel remained alive. Two real start/stop cycles with the revised cleanup left no marked processes; domain 219 was empty. The final real cycle still logged a Nav2 component `Magick` SIGSEGV during shutdown and Gazebo needed SIGTERM escalation. The earlier version simultaneously signaled all processes and also logged crashes; it was corrected before the last two cycles. These checks do not prove an absolute guarantee against inaccessible processes, an uninterruptible kernel task, lost process markers, supervisor SIGKILL or machine failure. If the supervisor is killed, run `stop` to recover any still-marked children. Do not kill unrelated processes.
3. **GPU: headless Gazebo accessed the GPU interface.** `LIBGL_ALWAYS_SOFTWARE=1` did not ensure CPU rendering on WSL: a matching Mesa EGL probe identified `D3D12 (NVIDIA GeForce RTX 4060 Laptop GPU)`, and the actual Gazebo Sim process had `/dev/dxg` open and loaded WSL `libd3d12`, `libd3d12core` and NVIDIA GPU compiler libraries. This establishes GPU interface/driver use, not the exact per-process allocation. `nvidia-smi` whole-GPU readings (used / free / total): before 936 / 7021 / 8188 MiB; during first Gazebo+Nav2 1062 / 6895 / 8188 MiB; after 931 / 7026 / 8188 MiB. Final run during 1054 / 6903 / 8188 MiB; after 921 / 7036 / 8188 MiB. The first before-to-during increase was 126 MiB, but other Windows/WSL graphics workloads can vary and WSL supplied no per-process compute attribution, so it is not a verified Gazebo-only allocation. About 6.7 GiB was free during these samples; future Ollama capacity depends on concurrent workloads and model/context memory. No model was loaded to test fit.

## Use

From the repository root, after checking that no other experiment is running:

```bash
uv run --no-project --python /usr/bin/python3 python research/studies/turtlebot3_nav2_smoke_20261116/stack.py start
source /opt/ros/jazzy/setup.bash
export ROS_DOMAIN_ID=219 ROS_LOCALHOST_ONLY=1
uv run --no-project --python /usr/bin/python3 python research/studies/turtlebot3_nav2_smoke_20261116/navigate_once.py
uv run --no-project --python /usr/bin/python3 python research/studies/turtlebot3_nav2_smoke_20261116/stack.py stop
```

`start` returns when the supervisor is launched, not when Nav2 is ready; the navigation script waits for readiness with timeouts. `status` in place of `start` or `stop` lists owned processes. Use `stop` even after an error; supervisor shutdown also attempts cleanup if a launch exits or it receives SIGTERM/SIGINT. The script only targets processes with its unique inherited `ROSA_TB3_RUN_ID`, and aborts if domain 219 is not empty. The bounded goal is in simulation only. The map centerline check does not prove that the whole robot footprint or the map alignment is collision-free in other worlds.
