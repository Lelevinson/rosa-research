# Steady loop and add-ons: lab-test handoff

**As of 17 November 2026; development evidence only. Method freeze: Saturday night, 21 November, Taipei time.** The owner chose the fixed C1 loop as the base; the final paper claim, add-ons, and lab evaluation are not yet frozen. The fairness test is running; wait for its completed report before interpreting it. Nothing here authorizes a held-out run.

**Example.** A model asks for a node's parameters with the wrong argument type. C1 checks the tool arguments before the original parser and returns a field-specific error as a tool observation, so the model can try again. It has 12 ROS/log read tools, plus a `final_answer` tool; the latter accepts a nonempty JSON object and ends the episode without another model request. The underlying executor blocks write operations. See [`harness.py`](../studies/small_model_harness_20261115/harness.py) (`PilotTool`, `PilotExecutor`, `Arm`); the model still decides what to investigate and what the answer means. No task-specific answer map is supplied.

**What is known.** On 80 same development cells, C1 scored 70/80, versus 47/80 for the original ROSA executor with a deconflicted prompt and 55/80 for Forge. The C1 rerun was 67/80; sessions, tool menus and finish mechanisms differ, so these are not causal component effects. Scorer v2.0 is frozen; include all failures and costs, and separate fixture defects. [Independent comparison](../studies/forge_baseline_20261115/INDEPENDENT_CHECK.md); [round 1](../studies/build_round1_20261115/REPORT.md). A live fairness test adds errors-as-text to the 47-tool original ROSA executor; it tests that contrast, not the C1 component removals. [Protocol](../studies/fairness_errors_as_text_20261117/PROTOCOL.md).

**Design implications.** Freeze the exact full system, arms, scorer, tasks and acceptance bars before lab model runs; a full-menu arm retains the finish tool and write guard. The owner selected the one-seed [ablation protocol](2026-11-17-steady-loop-ablation-protocol.md) with a fresh shuffled concurrent C1 primary control; historical C1 is sensitivity only. Run it only after fairness completes and the owner separately authorizes it. The approved [name-fix plan](2026-11-17-name-fix-applied-test.md) follows the ablation and uses separate synthetic dev tasks and strict plus separately frozen lenient scoring. The [finish check](2026-11-17-finish-gate-check.md) recommends no new gate; the [menu audit](2026-11-17-menu-coverage-and-rule.md) records aggregate coverage and unknowns. Preserve the 76 held-out tasks and their protected task-level contents; 31/76 request a full name, which only establishes a syntactic opportunity. Count complete supported answers before requests, input/output tokens, native reads, time, setup and failed episodes. A successful simulator result is not physical-robot evidence; document model settings, source hashes, resets, scripted-change validity and full denominators. **Owner clarification:** virtual-robot evaluation must include actions in simulation, after inspection tasks; the group still has to decide the action pool's scope.
