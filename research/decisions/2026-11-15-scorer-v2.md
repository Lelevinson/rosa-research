# Scorer decision: scorer v2.0 (frozen 2026-11-15)

Dated decision. It does not change or hide the earlier numbers: scorer v1 (`studies/small_model_harness_20261115/pilot_score.py`, sha256 `5d9de512...`) stays in place and its flags are stored in `RESULTS_LOG.jsonl`. v2 is a separate file.

## Why
[RESIDUAL_FAILURES.md](../studies/residual_failures_20261115/RESIDUAL_FAILURES.md) found that 6 of 15 failed C1 episodes were scoring artifacts: four gpt-oss answers written as `{"answer": {...}}` plain text, one gpt-oss answer that read a node as `plant32/oasis`, and one bonsai "not running" answer whose only evidence was a lookup without the leading slash.

## The two rules
1. **Leading slash (checked, not assumed).** `slash_check.py` (Stage 3 fixture, real tools, ROS 2 Jazzy, domain 220; output `slash_check.json`):
   - `ros2 param get plant32/anvil gain` returns the same value as `/plant32/anvil` (41), and `ros2 param list plant32/anvil` works: **parameter tools resolve the relative name**, so a parameter read with the relative form supports a task fact about the absolute node. Node names of param reads are normalised to `/` + name.lstrip('/') before the support check.
   - `ros2 node info plant32/anvil` fails with "Unable to find node 'plant32/anvil'" for a node that exists: **node_info does not resolve it**, so a failed relative-name node_info is not evidence that a node is absent. This keeps bonsai `abs_2` seed 1 (correct answer, only such evidence) **unsupported**; my earlier reading of that case as an artifact was wrong and is corrected in RESIDUAL_FAILURES.md. A failed param read of the relative form ("Node not found") is accepted as absence evidence because param tools resolve it.
2. **Wrapper.** If the final free text's last JSON object has exactly one key, `answer`, whose value is an object, the inner object is scored. A `final_answer` tool object is never unwrapped; any other shape is unchanged.
Everything else is identical to v1 (answer = `final_answer` object else last complete JSON object; exactness by the vendored `baseline_audit`; strict support).
