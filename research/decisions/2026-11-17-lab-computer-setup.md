2026-11-17. Preparation checklist for a later authorized session; do not start a GPU or ROS job while Round 2 is running. Match the eventual frozen protocol, and record discrepancies rather than changing a running study.

- **Access and persistence:** Set up an individually authorized SSH account and key; verify host identity using a separately trusted fingerprint. Test reconnecting. Use `tmux new -s rosa-study` to create a named terminal session, detach with Ctrl-b then d, and reconnect with `tmux attach -t rosa-study`. A session survives an SSH disconnect, not a reboot or a killed process. Enable persistent logs and arrange power, storage and access with the lab owner. Do not place credentials in the repository or results.
- **Source and Python:** Check out the exact approved commit and capture `git status --short`, including intentional local changes; transfer any authorized untracked study inputs separately with hashes. Install the matching Python and uv versions and use the project's documented locked environment (`uv sync --locked`); record `uv --version`, Python version and lockfile hash. - **Ollama and models:** Record server and client versions, model names and immutable model digests, model template and quantization, context size, inference options, tool schema and prompt hashes. Provision the exact versions and model bytes on both hosts; verify with the local Ollama inventory and model metadata. Record GPU, driver and memory. Different hardware or server builds can alter behavior or performance even when model digests match; do not infer bitwise identity.
- **ROS:** Match Ubuntu, ROS 2 Jazzy distribution and installed package versions; source `/opt/ros/jazzy/setup.bash` and any approved overlay. Transfer through an approved secure channel, verify file counts and hashes at both ends, then place results in the repository's designated artifact location without overwriting any previous run. Keep large traces and secrets out of Git; commit only approved compact reports and provenance. Apply the held-out access restrictions to all copies.
- **Matched check after authorization:** Before a full study, run the same predeclared small development check on each machine with the same revision, model digest, prompt, tools, settings, inputs and seed; compare environment manifests, structured-call validity, scoring, trace integrity and cost units. Match fixture setup and independently check truth. Record differences and stop if a protocol-critical mismatch remains. Exact generated text or latency need not match; report them and retain hardware as a factor. Do not use held-out tasks to tune this check.
