## Decision bar fixed now

**GO for a small live shadow measurement only if all:** (1) at least 10% of eligible C1-type episodes have a stall, so there is enough signal to observe on a small sample; (2) at least 5% of their recorded requests occur strictly after first stalls, so the opportunity could matter at whole-run scale; (3) no supported episode in the *entire* analyzed corpus has a second same-tool stall followed by a successful, nonempty, new result from that tool in the next request. The last is the earlier frozen safety bar: a hide would suppress observable useful progress. It already failed in the prior 400-episode replay; do not erase that negative to make this study pass. The 10% and 5% are pragmatic screening thresholds, not power calculations or proven benefits: they avoid spending the scarce pre-freeze slot on a rare or immaterial trigger. If any condition fails, **NO-GO for this combined first-hint/second-hide design**; the first-hint-only mechanism is a separate question and is not implicitly approved. If trace coverage is insufficient to establish a condition, **INCONCLUSIVE**, except a directly observed safety failure is sufficient for NO-GO. Shadow alone cannot establish that the intervention helps or is safe.

## Population and rules

All recorded, primary full-run development rows from the pilot (all arms, including A1), round 1 rerun (all arms), and round 2 (both arms); report groups and models separately and pooled without claiming independent episodes. Exclude separately labeled smoke, superseded/infrastructure-excluded attempts, and duplicate trace paths; report missing/unparseable traces. Fairness E0/E1 is included only after its full run is complete and results recorded; never read an active partial result as final. No hidden-task files or per-task examples. Scorer v2 supported-complete flags, with existing adapters for sweep/list calls, are used from finalized logs/rescoring and invalid episodes retain frozen labels.

Use existing `episodes.py` call units: compare exact tool + serialized result text irrespective of arguments; also report exact-argument sensitivity. Empty means empty string/list/dict or a nonempty dict whose values are all empty list/dict/null/string; not-found means the existing replay regex `not found|Unable to find|does not exist|no such`. An error dictionary counts as not-found only when its text matches that regex. Unlike the older replay, include recorded handler errors when they match the supplied rule; exclude missing results rather than treating them as empty. Reset all tools' empty counters whenever a successful result adds any full ledger name; task-text names seed the ledger. Rule b counts the second **and subsequent** empty/not-found call until reset, matching the prior replay's operationalization. Count the union once if both rules fire; process calls in logged order, including multiple calls in one request. Ignore finish-tool calls. This operationalization is a trace approximation, not semantic identity or proof of a live detector; this population and error handling differ from the older replay, so its result is not a numeric cross-check.

Per episode record all stalls, first and second stall overall, and first second stall **for the same tool** (the hide point); if multiple calls are in one request, both can occur before the model receives feedback. Count requests and reported input+output tokens from model requests strictly after the trigger request; this cannot measure the rest of the triggering request, and the first/second totals overlap and are not additive or predicted savings. Missing token usage stays unknown and is counted; never silently replace missing usage with zero. Count supported episodes with >=1 stall and number of their stalls as an exposure/harm upper bound, not demonstrated harm. Count 40-request-cap episodes from the log/events, and distinguish >=40 observed requests from actual cap termination. For the safety check replay every tool's second stall, not merely the episode's second overall; check next-request successful, nonempty previously unseen result of that tool, as in the old replay. No counterfactual trajectory is asserted.

Report per-episode records and aggregate denominators, group/model, exclusions, incomplete fairness, parser limits, and selection. C1-type = pilot C1 + round-1 C1 + round-2 CONTROL, separately report round-2 CONTROL seeds 1–2 vs enriched additional seeds. Do not merge SWEEP as C1; its additional tool calls change trajectories. Do not adjust bars after seeing counts.
